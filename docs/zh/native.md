# 原生代码

Asuka 没有封装的功能，应用可以通过**原生包**来使用。原生包用 Asuka 声明一个模块（`native interface`）或一个视图（`native component`），再由每个平台用自己的语言实现：iOS 和 macOS 上用 Swift，Android 上用 Kotlin，Web 上用 JavaScript，Windows 和 Linux 上用 C。`asuka native generate` 会为每一端生成带类型的胶水代码。在 Asuka 里，调用模块的方法和调用任何方法一样，显示视图也和显示任何组件一样。值以紧凑的二进制格式在两端之间传递，不经过 JSON，也不用反射。

```asuka
/// 设备的电池。
pub native interface Battery {
  /// 电量，范围是 0 到 1。
  fn level() -> float
  /// 在电量变化时调用 changed，直到 task 被取消。
  async fn watch(changed: fn(float))
}
```

```asuka
let battery = try Battery()
let level = try battery.level()
```

```swift
// swift/Battery.swift
final class IOSBattery: Battery {
    func level() throws -> Double {
        UIDevice.current.isBatteryMonitoringEnabled = true
        return Double(UIDevice.current.batteryLevel)
    }
    ...
}
func makeBattery() throws -> any Battery { IOSBattery() }
```

原生包就是一个普通的 Asuka 包：它可以放在应用里，也可以作为应用的依赖（见[包](packages.md)），导入它的每个应用都会带上它的原生代码。每个平台的代码放在该平台自己的项目里（Swift 包、Gradle 模块），使用该平台自己的依赖管理工具：SwiftPM 和 Maven。

## 什么时候需要它

Asuka 的组件、标准库（`std/...`）和平台 SDK（`platform/...`）已经覆盖了大多数应用需要显示和使用的功能，[与 SwiftUI 和 Expo 的对比](parity.md) 中列出了它们。如果你需要某个还没有被封装的平台 API、某个厂商的 SDK，或者 Asuka 没有提供的视图（地图、图表、只有某个平台才有的控件），就可以写一个原生包。

原生包只需要为应用实际运行的平台提供代码。在没有代码的平台上，创建模块时会抛出一个 `unsupported` 错误，视图则什么都不显示（日志中会提示缺少这个视图）。

如果要用的库提供的是 C API，或者这段代码你本来就会用 C 来写，那就直接调用 C：一个 `extern fn` 只是一条声明，同一份 C 代码在所有平台上运行（Web 也一样，编译进 WebAssembly 模块），而且一次调用只做参数类型需要的转换，不经过任何编码。原生包适用于只有平台自己的语言才能访问的东西（UIKit、Android 的 API、DOM、厂商的 Swift 或 Kotlin SDK），以及视图。详见[在 Asuka 中调用 C](c.md)。

## 创建原生包

原生包就是一个声明了原生模块的库（见[包](packages.md#编写包)），所以用 `asuka new` 创建：

```sh
asuka new --lib --native ./battery          # Asuka、Swift、Kotlin、JavaScript，以及桌面端的 C
asuka new --lib --native --projects swift,android ./battery
asuka native add web ./battery              # 之后再添加某个平台的项目
```

`asuka new --lib --native` 会生成一个在所有平台上都能编译和运行的库，其中有一个 `hello` 方法，每一端都实现了它。你只需要重命名并补充内容。一个原生包的结构如下：

```
battery/
  asuka.toml               包的名字和版本
  battery.asuka            声明：native interface、native component
  Package.swift            Swift 包，用于 iOS 和 macOS
  swift/
    Battery.swift          你写的：makeBattery
    Battery.asuka.swift    生成的：协议、类型、提供者
  android/
    build.gradle.kts       Gradle 库模块
    src/main/AndroidManifest.xml          （可选）权限、服务
    src/main/kotlin/com/example/battery/
      Battery.kt           你写的：makeBattery
      Battery.asuka.kt     生成的
  web/
    battery.js             你写的：export function makeBattery
    battery.asuka.js       生成的
    battery.decl.asuka.js  生成的：包中的枚举和错误（有的话）
  desktop/                 Windows 和 Linux 的 C 实现
    battery.c              你写的：battery_make_Battery（_windows.c、_linux.c 只用于一个平台）
    battery.asuka.h        生成的：类型、vtable、你要写的函数
    battery.asuka.c        生成的：编解码、provider
  Info.plist               （可选）这个包对 Apple 应用的要求
  iOS.entitlements         （可选）
  macOS.entitlements       （可选）
```

生成的文件以 `// Code generated by asuka native. DO NOT EDIT.` 开头，并带有声明内容的哈希值。把它们提交到仓库。

- `asuka dev` 和 `asuka build` 会在构建前重新生成应用自己的原生包，所以修改声明后保存就会生效。
- 应用所依赖的原生包会自带生成的代码。CLI 会检查这些代码是否与声明一致，不一致时会报错，并告诉你该运行什么命令。
- `asuka native generate [dir]` 可以手动生成。`asuka native check` 在有任何内容过期时报错，适合在 CI 中使用。

## 声明模块

`native interface` 就是一个模块：

```asuka
/// 厨房的错误。
pub enum KitchenError: Error {
  /// kitchen: busy
  busy
}

pub enum Level { low, high }

pub struct Item {
  name: string
  weight: float
  level: Level
  tags: [string]
  best: Duration?   // 可选
}

pub native interface Kitchen {
  fn name() -> string
  fn items(filter: string) -> [Item]
  async fn cook(recipe: string, progress: fn(float)) -> Item
  fn ask(question: fn(string) -> bool) -> bool
  fn open(name: string) -> Oven
  /// @mainThread
  fn show()
}

/// @mainThread
pub native interface Oven {
  fn heat(to: float, level: Level)
  fn close()
}
```

`Kitchen()` 会创建平台的实现：如果创建失败，它抛出平台给出的错误；如果包没有为当前平台提供代码，它抛出一个 `unsupported` 错误。每个方法都可能抛出错误（平台端总有可能失败），所以调用时都要写 `try`。

### 类型

| Asuka | Swift | Kotlin | JavaScript | C |
| --- | --- | --- | --- | --- |
| `bool` | `Bool` | `Boolean` | `boolean` | `bool` |
| `int` | `Int` | `Long` | `bigint` | `int64_t` |
| `float` | `Double` | `Double` | `number` | `double` |
| `string` | `String` | `String` | `string` | `char *`，UTF-8，以 NUL 结尾 |
| `bytes` | `Data` | `ByteArray` | `Uint8Array` | `asuka_bytes`（`data`、`len`） |
| `Duration` | `TimeInterval`（秒） | `kotlin.time.Duration` | `number`（毫秒） | `int64_t`（纳秒） |
| `Decimal`（导入的 std/decimal 的） | `Decimal` | `java.math.BigDecimal` | `string`，它的精确文本（`"19.99"`） | `asuka_decimal`（`coefficient`、`exponent`；`asuka_decimal_text`、`asuka_decimal_parse`） |
| `[T]` | `[T]` | `List<T>` | `Array` | `<pkg>_list_T`（`data`、`len`） |
| `[string: T]` | `[String: T]` | `Map<String, T>` | `object` | `<pkg>_map_T`（`keys`、`values`、`len`） |
| `T?` | `T?` | `T?` | `T` 或 `null` | `T *`（`NULL` 表示没有值；`string?` 是 `char *`） |
| `Color` | `Int`，即 Asuka 的编码：`AsukaColors.color(_:)` 把它变成 `UIColor` 或 `NSColor`（语义色会跟随浅色和深色模式） | `Long`：`AsukaModules.color(v, fallback)` 把它变成 ARGB 的 `Int` | `bigint`：`native.color(v)` 把它变成 CSS 颜色（语义色是一个 CSS 变量） | `uint64_t`：`asuka_desktop_color(v)` 按当前的外观把它变成 RGBA |
| 包中定义的结构体 | 结构体（包含自身时为 final class） | data class | 对象 | 结构体 `<pkg>_Name` |
| 包中定义的枚举（成员不带值） | `RawRepresentable` 结构体，每个成员对应一个静态成员 | value class，每个成员对应一个常量 | 由这些成员组成的冻结对象 | `int64_t`，每个成员对应一个常量（`<pkg>_Level_low`） |
| `native interface`（作为参数或返回值） | `any T` | `T` | 对象 | `<pkg>_T *` |
| `fn(...)`（作为参数） | 闭包 | 函数 | 函数 | `<pkg>_fn_…`，用它的 `_call` 调用 |
| `Ref`（作为参数） | `AsukaViewRef`：它的 `view`（在主 actor 上读取）是 Asuka 显示的 `UIView` 或 `NSView`（WebView 的是 `WKWebView`），没有时为 `nil` | `AsukaViewRef`：它的 `view`（在主线程上读取）是对应的 `View`（WebView 的是 `WebView`），没有时为 `null` | 对应的元素，或 `null` | `uint32_t`，即视图的 id：`asuka_desktop_view(v)` 是它的 `HWND` 或 `GtkWidget *`，`asuka_desktop_webview(v)` 是 WebView 的 `ICoreWebView2 *` 或 `WebKitWebView *` |

结构体的字段按声明顺序传递；它的常量和方法只留在 Asuka 这一端。对象（原生接口）只能作为参数或返回值传递，不能放在数组、map 或结构体里。`Ref` 只能作为参数传递：传过去的是调用时它所持有的视图（platform/print 的 `webView(view: Ref, …)` 打印的就是用 `ref:` 放进去的那个 WebView 的页面），平台代码在主线程上查找这个视图；如果 Ref 里没有视图，或者 Asuka（还）没有显示它，得到的就是 `nil`。其他不支持的用法，`asuka native generate` 都会在对应位置报错，并告诉你应该改用什么。

`Decimal`（`import std/decimal.{Decimal}`）按系数和指数精确传递；平台一端传回的值如果超过 18 位有效数字，会按四舍六入五成双舍入，因为 Asuka 容纳不了更多位。Swift 的 `Decimal` 只能表示 -128 到 127 的指数，超出这个范围就成了 NaN。

### 方法

- **错误。** 平台端抛出的错误会以下面几种形式返回：
  - 包中声明的某个错误（声明为 `: Error` 的枚举的成员，成员的 `///` 文档就是错误消息）。平台端这样抛出它：Swift 中是 `KitchenError.busy`，Kotlin 中是 `KitchenException(KitchenError.BUSY)`，JavaScript 中是 `new KitchenError("busy")`，C 中是 `asuka_error_declared(err, kitchen_KitchenError_busy)`。在 Asuka 中用 `catch KitchenError.busy` 捕获它。
  - `AsukaNativeError.unsupported(msg)`、`AsukaUnsupportedException`、`asuka.native.UnsupportedError` 或 `asuka_error_unsupported`：它们会变成一个 `unsupported` 错误。
  - 其他任何错误，都会变成一个带有域（`NSError` 的域，或异常的类名）、错误码和消息的错误。
- **`async`** 让方法变成异步的：在 Swift 中是 `async`，在 Kotlin 中是 `suspend`，在 JavaScript 中是一个第一个参数为 `AbortSignal` 的 `async` 函数，在 C 中是一个接收 `asuka_call` 的函数，它要在任意线程上对这个调用应答一次。Asuka 等待它的结果时不会占住主线程。task 被取消时（比如启动它的页面已经离开），平台端的任务也会被取消（Swift 的 task、Kotlin 的协程、`AbortSignal` 的 abort、C 的 `asuka_call_on_cancel`）。凡是耗时的操作都应该这样写：网络、文件、等待对话框的回答。
- **回调。** `fn` 参数分为两种：
  - **通知**：不返回任何值的函数（`progress: fn(float)`）。平台端可以在任意线程上调用它任意多次，无论是在调用进行中还是返回之后（比如监听器）。它在 Asuka 中的主线程上运行，因此可以写入状态。
  - **询问**：有返回值的函数（`question: fn(string) -> bool`）。它会立即运行，结果返回给平台端。

  回调的生命周期与接收它的对象相同。
- **对象。** 方法可以返回另一个原生接口（`open` 返回一个 `Oven`）。每个返回的接口在平台端都是一个独立的对象。当 Asuka 不再持有它，或者它的 `close()`（一个名为 `close`、没有参数的方法）被调用时，它就会被释放。
- **线程。** 方法在平台端同步运行，所在线程就是发起调用的主线程：中间没有线程切换，也没有队列。这让调用的开销很小，但耗时的调用会占住主线程，所以要把这样的方法声明为 `async`。
  - 在方法或接口的 `///` 文档里写上 `@mainThread`，就能确保它在平台的主线程上运行，UIKit、AppKit 和 Android 的视图都要求这样做。这时 Swift 中的协议会标注为 `@MainActor`。
  - JavaScript 是单线程的，所以这些在 Web 上不适用；Windows 和 Linux 上的 C 代码所有调用都在主线程上运行。

## 声明视图

`native component` 就是一个视图：

```asuka
pub native component Segmented(items: [string]) {
  prop selected: int = 0
  event selectedChange(selected: int)
}
```

在 Asuka 中显示它，和显示任何组件一样：

```asuka
state selected = 0

segmented.Segmented(["Day", "Week", "Month"]) {
  bind selected: selected
}
```

- 每个属性都会跟随它读取的值：值变化时，平台端的 setter 会再次运行，而且只在变化时运行。
- 事件在主线程上运行。
- `bind name: target` 绑定一个属性，前提是视图用与属性同类型的事件 `nameChange(name: T)` 报告它：用户改变值时（而不是应用设置值时）视图发送这个事件，由它写入 target。
- 它接受所有元素都接受的样式。

每个平台都以协议的形式实现视图：包括视图本身、每个属性对应的 setter，以及创建时传入的事件对象：

```swift
@MainActor final class SwiftSegmented: Segmented {
    let control = UISegmentedControl()
    let events: SegmentedEvents
    var view: AsukaPlatformView { control }          // iOS 上是 UIView，macOS 上是 NSView
    init(_ events: SegmentedEvents) { self.events = events; ... }
    func setItems(_ value: [String]) { ... }
    func setSelected(_ value: Int) { ... }
    // 值变化时：events.selectedChange(selected: i)
}
@MainActor func makeSegmented(_ events: SegmentedEvents) -> any Segmented { SwiftSegmented(events) }
```

属性的设置顺序是不确定的，所以如果视图依赖其中两个属性（比如从若干项中选中一项），就要先把收到的值保存下来，等两者都到齐后再一起应用。Asuka 会像处理自己的视图一样确定它的尺寸：

- Swift 中用 `sizeThatFits`（iOS）或 `fittingSize`（macOS），如果视图遵循 `AsukaSizing`，则用它的 `sizeThatFits`；
- Android 上用视图自己的测量逻辑；
- JavaScript 中用 `measure(c)`；
- C 中用 vtable 的 `measure`，没有时用控件自己的尺寸（见下文）。

没有固有尺寸的视图，尺寸由它的样式决定。如果视图持有需要释放的资源，在 Swift 中让它遵循 `AsukaDestroying`，在 JavaScript 或 C 的 vtable 中给它一个 `destroy`。

`examples/media/segmented` 是一个在所有平台上都完整实现的视图示例。

在应用的测试里（`asuka test`，没有平台代码），原生视图显示为它的组件名，`app.tap("Segmented")` 会给它发送一个 `press` 事件，就像平台上的按钮被按下一样。

## 应用需要什么

包对应用的需求（权限、用途说明、后台模式、entitlement）由包自己声明，而且只有用到它的应用才会得到。这些写在包的 `asuka.toml` 里；下面这些表对每个导入这个包的应用都生效：

```toml
[ios]
usage = { NSLocationWhenInUseUsageDescription = "To show where you are." }
backgroundModes = ["audio"]
entitlements = { aps-environment = "development" }   # 模拟器构建用的值
plist = { LSApplicationQueriesSchemes = ["mailto"] } # true、字符串，或与应用的合并的数组

[android]
permissions = ["android.permission.ACCESS_FINE_LOCATION", "android.permission.WRITE_EXTERNAL_STORAGE:28"]
application = ['<service android:name="com.example.battery.Watcher" android:exported="false" />']
manifest = ['<queries><intent><action android:name="android.intent.action.TTS_SERVICE" /></intent></queries>']
```

权限写成 `"name:28"` 表示只到这个 API 级别；写成 `"name|neverForLocation"` 会带上它的 `usesPermissionFlags`。应用自己的 `asuka.toml` 里的用途说明优先于包的。

只有包的一部分才需要的东西，写在 `[uses.<member>]` 表里，键和上面相同：只有当应用的代码（或某个依赖的代码）引用了这个成员（函数、类型、store；类型的方法或字段写成 `"Type.name"`。字段只有在代码构造结构体时给了它、给它赋值或读取它时才算，保持默认值不算）时，应用才会得到它。同名的本地函数不算，测试块里的引用也不算。platform/location 的后台部分就是这样声明的：

```toml
[uses.requestAlways.android]
permissions = ["android.permission.ACCESS_BACKGROUND_LOCATION"]

[uses.startUpdates.ios]
backgroundModes = ["location"]
```

包代码旁边的文件对每个导入它的应用都生效：Gradle 模块的 `AndroidManifest.xml`，Swift 包的 `Info.plist` 和 entitlements（见下文）。每个用到这个包的应用都需要的东西放在那里，某一个成员才需要的放在 `[uses]` 里。

## iOS 和 macOS：Swift

包中的 Swift 代码是一个 Swift 包：`Package.swift` 位于包的根目录，源码放在 `swift/` 中。同一个包同时服务 iOS 和 macOS，两者有差异的地方用 `#if canImport(UIKit)` 区分：

```swift
// swift-tools-version:5.9
import PackageDescription

let package = Package(
    name: "BatteryNative",
    platforms: [.iOS("16.0"), .macOS("11.0")],
    products: [.library(name: "BatteryNative", targets: ["BatteryNative"])],
    dependencies: [
        .package(url: "https://github.com/egoist/asuka", from: "0.1.0"),
        .package(url: "https://github.com/firebase/firebase-ios-sdk", from: "11.0.0"),
    ],
    targets: [
        .target(name: "BatteryNative", dependencies: [
            .product(name: "Asuka", package: "asuka"),
            .product(name: "FirebaseAnalytics", package: "firebase-ios-sdk"),
        ], path: "swift"),
    ]
)
```

这个包完全由你掌控：它的依赖、target、资源、C target 和二进制 target 都是标准的 SwiftPM 写法，和任何 Swift 包一样。Asuka 会把它和应用以及应用的其他原生包一起构建，链接进应用（静态的二进制框架会整个链接进去，这正是厂商 SDK 所要求的），并把生成的动态框架和资源包嵌入应用。`asuka`（产品名为 `Asuka`）是生成的代码所依赖的库；构建时使用的是你的 `asuka` 自带的那份，所以它总是与应用的 Asuka 版本一致。包中声明的 `platforms` 会真正起作用：如果应用的目标 iOS 或 macOS 版本更低，构建会失败并说明这个包的要求；只列出其中一个平台的包（`platforms: [.iOS("16.0")]`）只会为那个平台构建。Apple TV 的构建只包含列出了 tvOS（`.tvOS("17.0")`）的包：见[电视](tv.md#tvos-上的原生包)。

要在 Xcode 中编辑它，打开 `Package.swift` 即可。Xcode 会从 URL 解析 `asuka`，所以生成的代码和你的代码在 Xcode 里的类型检查结果和构建时一致。

你的 Swift 代码要为每个接口和每个视图各提供一个函数，生成文件的头部会列出它们：

```swift
func makeKitchen() throws -> any Kitchen
@MainActor func makeOven() throws -> any Oven      // 一个 @mainThread 接口
@MainActor func makeDial(_ events: DialEvents) -> any Dial
```

在平台端创建、再交给 Asuka 的对象（比如 `open` 返回的 `Oven`）由你的代码创建。如果要在后台方法中创建一个 main actor 对象，可以用 `try AsukaNative.onMain { SwiftOven() }`。

`Package.swift` 旁边的 `Info.plist` 声明这个包对 Apple 应用的要求：

- 权限用途说明（如 `NSBluetoothAlwaysUsageDescription`）：如果应用自己在 `asuka.toml` 中提供了，以应用的为准；
- 数组类型的键（如 `UIBackgroundModes`）：会与应用和其他包的值合并；
- 其他任何键：除非应用自己设置了，否则就使用包里的值。

`iOS.entitlements` 和 `macOS.entitlements` 声明它需要的授权（entitlements）。如果描述文件缺少其中某项，签名构建会失败，并指出是哪个包要求的。

## Android：Kotlin

包中的 Kotlin 代码是 `android/` 下的一个 Gradle 库模块：

```kotlin
// android/build.gradle.kts
plugins {
    id("com.android.library")
    id("org.jetbrains.kotlin.android")
}

android {
    namespace = "com.example.battery"
}

dependencies {
    implementation("com.google.code.gson:gson:2.11.0")
}
```

Kotlin 源码放在 `src/main/kotlin/` 下，包名与生成文件中的一致：也就是包的名称（asuka.toml 的 `name`），各段转为小写，主机名倒过来放在最前面（`@acme/battery` 对应 `_acme.battery`，`github.com/you/battery` 对应 `com.github.you.battery`）。CLI 会把这个模块加入应用的 Gradle 构建，并统一设置以下内容，所以模块里只需要写命名空间和依赖：

- SDK 版本、Java 17 和 Kotlin 工具链；
- 对 Asuka 的 Android 库（`dev.asuka`）的依赖，它会带入 AndroidX、Material Components 和协程。

模块的 `src/main/AndroidManifest.xml`（权限、服务、广播接收器、内容提供者）会合并到应用的清单中，和任何库一样。

```kotlin
private class AndroidBattery(private val context: Context) : Battery {
    override fun level(): Double { ... }
    override suspend fun watch(changed: (Double) -> kotlin.Unit) { ... }
}
fun makeBattery(): Battery = AndroidBattery(AsukaModules.context)
```

`AsukaModules.context` 是应用的 application context，可以在任何线程上使用；`AsukaModules.activity` 是当前显示应用的 activity（如果有的话），供需要 activity 的操作使用（对话框、权限请求），要在主线程上使用。视图的事件对象中有创建该视图时使用的带主题的 context（`events.context`）。`AsukaModules.onMain { }` 会在主线程上创建对象，作用和 Swift 的 `AsukaNative.onMain` 相同。生成的代码里，Kotlin 的 `Unit` 写作 `kotlin.Unit`，所以你可以放心地定义名为 `Unit` 的类型。

想在编辑模块时获得代码补全，可以在 Android Studio 中打开应用的 Android 项目（由 `asuka build --platform android` 生成）。原生包的模块在其中以 `:native-<package>` 的形式出现。

## Web：JavaScript

包中的 JavaScript 是 `web/<package>.js`，它是一个 ES 模块，导出生成的 `web/<package>.asuka.js` 所导入的那些函数：

```js
export function makeBattery() {
  return {
    async level() { return (await navigator.getBattery()).level; },
    async watch(signal, changed) { ... },
  };
}

export function makeSegmented(events) {
  const el = document.createElement("div");
  return { el, setItems(v) { ... }, setSelected(v) { ... }, measure: () => [216, 32] };
}
```

方法可以返回 promise，即使它在 Asuka 中不是 `async` 的。要抛出包中声明的错误，就使用生成的错误类（`import { KitchenError } from "./kitchen.asuka.js"`）。包中的枚举和错误会在包自己的模块运行之前创建好，所以模块加载时就可以读取它们（比如按枚举的取值建一张表）；如果导入了包中没有声明的名字，`asuka native generate` 会报错。`web/` 中的每个文件都会随应用一起发布，所以模块可以导入自己的辅助脚本，也可以相对于 `import.meta.url` 获取自己的资源。其中任何文件变化时，`asuka dev --platform web` 都会重新加载页面。参见 [Web](web.md#原生代码)。

## Windows 和 Linux：C

包在 Windows 和 Linux 上的代码是 C，放在它的 `desktop/` 目录里，编译进应用的可执行文件（在其他系统上构建时用 Zig）。文件名以 `_windows.c` 或 `_linux.c` 结尾的文件只在对应的平台上构建，其他文件两个平台都构建，有差别的地方用 `#ifdef _WIN32` 区分；某个平台上没有包自己的任何文件时，包在那里就没有代码，创建它的模块会抛出 `unsupported`。`asuka native generate` 会生成你的代码要包含的 `<package>.asuka.h`：包的类型、每个接口一个 vtable，以及你要写的函数，每个接口和每个视图各一个：

```c
// desktop/battery.c
#include "battery.asuka.h"

#include <stdlib.h>
#ifdef _WIN32
#include <windows.h>
#else
#include <stdio.h>
#include <time.h>
#endif

// level_now 是电池的电量，从 0 到 1（负数表示没有电池）。
static double level_now(void) {
#ifdef _WIN32
	SYSTEM_POWER_STATUS s;
	return GetSystemPowerStatus(&s) && s.BatteryLifePercent <= 100 ? s.BatteryLifePercent / 100.0 : -1;
#else
	FILE *f = fopen("/sys/class/power_supply/BAT0/capacity", "r");
	int n = -100;
	if (f) {
		if (fscanf(f, "%d", &n) != 1) n = -100;
		fclose(f);
	}
	return n / 100.0;
#endif
}

static double level(battery_Battery *self, asuka_error *err) {
	double l = level_now();
	if (l < 0) asuka_error_unsupported(err, "no battery");
	return l;
}

typedef struct {
	battery_fn_float changed;
	asuka_call *call;
} watching;

// run 在自己的线程上每秒读一次电量，直到监听它的 task 被取消。
static void run(void *p) {
	watching *w = p;
	double last = -2;
	while (!asuka_call_cancelled(w->call)) {
		double l = level_now();
		if (l != last) battery_fn_float_call(w->changed, l);  // 会被投递到主线程
		last = l;
#ifdef _WIN32
		Sleep(1000);
#else
		nanosleep(&(struct timespec){1, 0}, NULL);
#endif
	}
	asuka_error e = {0};
	asuka_error_cancelled(&e);
	asuka_call_fail(w->call, &e);
	free(w);
}

static void watch(battery_Battery *self, battery_fn_float changed, asuka_call *call) {
	watching *w = malloc(sizeof *w);
	*w = (watching){changed, call};
	asuka_desktop_spawn(run, w);
}

static const battery_Battery_vtable vt = {.level = level, .watch = watch};

battery_Battery *battery_make_Battery(asuka_error *err) {
	battery_Battery *b = malloc(sizeof *b);
	b->vt = &vt;
	return b;  // Asuka 不再持有它时释放（vtable 里没有 release）
}
```

- **调用**在主线程上运行，平台的界面也在那里：同步方法直接返回结果，不能阻塞；失败的方法设置 `err` 并返回零值。`async` 方法接收一个 `asuka_call` 并立即返回：之后在任意线程上用生成的 `_done`（`battery_Battery_watch_done`）或 `asuka_call_fail` 应答一次。`asuka_call_cancelled` 和 `asuka_call_on_cancel` 告诉你发起调用的 task 什么时候离开了；`asuka_call_off_cancel` 再把取消回调撤掉，这样它的上下文可以在调用应答之前释放。会阻塞的工作用 `asuka_desktop_spawn` 放到单独的线程上。
- **内存**：所有跨边界的值都用 `malloc` 分配。方法的参数归生成的代码所有，同步调用期间有效，异步调用在应答之前有效（要保留得更久就复制一份）；方法返回（或应答）的值交给生成的代码，由它释放（字面量要先 `asuka_strdup`）。回调的参数仍归你；问题型回调返回的值由你释放（`<pkg>_<Type>_free`）。vtable 的 `release` 为 `NULL` 时，Asuka 不再持有对象时会直接释放它。
- **回调**：用 `<pkg>_fn_…_call` 调用。通知型回调可以在任意线程上调用（会被投递到主线程）；问题型回调在主线程上立即运行，在其他线程上调用时会等待它的结果。
- **视图**：`<pkg>_make_<View>(events)` 创建视图的对象和它的 `widget`，即一个 `HWND`（`events.parent` 的子窗口）或一个 `GtkWidget *`，Asuka 负责显示它，并在视图离开时销毁它。每个属性在 vtable 里有一个 setter（`set_selected`）；控件自己给不出尺寸时，由 `measure` 决定尺寸；事件是生成的函数（`segmented_Segmented_selectedChange(events, i)`），可以在任意线程上调用。
- **Asuka 的 C API**：`asuka_desktop.h` 是包的 C 代码在桌面端可以使用的 Asuka 功能：投递到主线程、视图所在的窗口、应用的名称、ID、版本和目录、资源目录、按当前外观解析的颜色、HTTP（`asuka_fetch`；要逐段接收响应、把下载直接写进文件时用 `asuka_fetch_stream`，要从任意线程中止请求时用 `asuka_abort`），以及应用指定的文件（`asuka_desktop_local_file`）。`asuka_windows.h` 提供 COM 和 WinRT 的辅助函数（UTF-16、vtable 的槽位、HSTRING、激活工厂、委托、等待异步操作、WIC 的图片、系统窗口收到的广播）；`asuka_barcode.h` 从图像的灰度中读取二维码和条形码，所有桌面平台都能用；`asuka_linux.h` 声明了包要用的 GLib、GIO、GTK 和 libadwaita 函数，在运行时解析（调用方式是 `G(g_variant_new)(…)`），所以构建时不需要 GTK 的头文件。
- **库**：包的 C 代码在各平台上要链接的库写在它的 `asuka.toml` 里：

  ```toml
  [windows]
  libraries = ["ole32", "winhttp"]
  [linux]
  libraries = []
  ```
- **Flatpak 里缺少的系统库**：包的 Linux C 代码在运行时打开（`asuka_linux_load`）、而 GNOME 运行时里没有的库，由包提供的模块编进 Flatpak：写在它的 `linux.flatpakModules` 里，每一项是清单里的一个模块（YAML，从 `name:` 那一行开始），在应用之前构建（platform/pdf 就是这样构建 Poppler 的）。
- **自带的库**：包构建时用到的 C 库（解析器、解码器）放在 `desktop/third_party/<名字>/` 里，不做修改，附上它的许可证和版本；由包自己的某个文件引入它的源码（`#include "third_party/<名字>/<名字>.c"`），这样它和包的 C 代码一起编译，改动它也会让应用重新构建。

在 macOS 上运行的是包的 Swift 代码（它的 `Package.swift`），不运行它的 C 代码。

## 开发原生代码

- **iOS 和 Android**：`asuka dev` 会构建包含原生包的应用外壳并安装，原生代码变化时重新构建，Swift、Kotlin、`Package.swift`、`build.gradle.kts`、`Info.plist` 和清单文件的修改都包括在内；应用的 Asuka 代码在保存时直接重新加载，不需要重新构建。没有原生包的应用则以热重载模式运行在开发 App 里，开发 App 只包含 Asuka 自己的原生代码。参见 [开发](development.md#开发-app)。
- **macOS**：原生包的 Swift 代码会构建进应用的 Swift 库，同样只在有变化时才重新构建，然后应用重新运行，状态会保留下来。
- **Windows 和 Linux**：原生包的 C 代码会构建进应用的可执行文件，同样只在有变化时才重新构建。
- **Web**：包的 JavaScript 变化时，页面会重新加载。

一个包在 iOS 或 macOS 上第一次构建时会解析它的 Swift 依赖，之后的构建会复用它们。

## 限制

- `asuka build --platform ios --xcframework`（把应用嵌入你自己的 Xcode 项目）不支持带 Swift 代码的原生包：请改为把它们的 Swift 包添加到那个项目中。
- `asuka build --platform android --aar` 不包含原生包的模块：请把它们添加到嵌入该产物的 Gradle 项目中。
- 如果两个原生包的目录同名，它们不能都带有 Swift 代码：SwiftPM 是按目录名识别本地包的。
