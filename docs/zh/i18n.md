# 多语言

Asuka 应用会用用户的语言显示文案，并按照这种语言的阅读方向来布局。文案存放在目录（catalog）里，每种语言一个 JSON 文件，由编译器读取：用 `tr.key(…)` 就能取出其中一条文案，并且在编译应用时就会检查。

```json
{
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}"
}
```

```asuka
component Inbox {
  state count = 3

  Column {
    Text(tr.unread(count: count))   // "3 unread messages"；"3 ungelesene Nachrichten"
    Button(tr.markAllRead()) { on press { count = 0 } }
  }
}
```

显示的内容会随 `count` 变化，语言切换时也会跟着变化，这些都不需要你写任何代码。

## 快速开始

```sh
asuka i18n init          # 生成 locales/en.json
asuka i18n add de ar     # 生成 locales/de.json 和 ar.json，附带待翻译的文案
```

如果应用有一个存放目录文件的 `locales` 目录，就不需要任何配置。如果文件放在别处，或者应用的源语言不是英语，请在 `asuka.toml` 里说明：

```toml
[i18n]
dir = "translations"
source = "ja"
```

`source` 是编写应用时使用的语言（默认是 `en`；如果只有一个目录文件，就是那一个）：它的目录包含所有文案，其他语言缺失的文案都会回退到它。应用支持哪些语言，取决于目录下有哪些文件，文件以 [BCP 47](https://www.rfc-editor.org/info/bcp47) 语言标签命名，比如 `de.json`、`pt-BR.json`、`zh-Hans.json`。

不需要生成任何代码，也不需要导入任何东西：`asuka dev` 在编译时直接读取目录文件，所以译文保存后立即就能看到；发布构建则会把目录文件编译进应用。

## 目录文件

目录文件是一个由文案组成的对象，采用 [ARB](https://github.com/google/app-resource-bundle) 格式，键就是文案的名字。源语言的目录还会在带 `@` 前缀的键下为文案添加说明，供译者参考，也会显示在编辑器的悬停提示里：

```json
{
  "@@locale": "en",
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}",
  "@unread": {
    "description": "Above the list of messages.",
    "placeholders": { "count": { "type": "int", "example": "3" } }
  },
  "markAllRead": "Mark all as read",
  "greeting": "Hello, {name}!",
  "lastSeen": "Last seen {when, date, medium} at {when, time, short}",
  "storage": "{used, number, percent} of your storage is used",
  "@storage": { "placeholders": { "used": { "type": "double" } } }
}
```

键以字母开头，后面跟字母、数字或 `_`，在 `tr.` 后面原样写出键名即可：`tr.markAllRead()`。键没有层级：相关的文案可以用相同的前缀命名，比如 `inboxTitle` 和 `inboxEmpty`，这样它们在编辑器的自动补全里会排在一起。

文案里的参数就是调用时的参数，按名字传入：`tr.greeting(name: "Ada")`。只有一个参数的文案可以省略参数名：`tr.greeting("Ada")`。参数的类型由占位符的类型决定：

| 占位符 | 接受 |
|---|---|
| `String`、`Object` | `string` |
| `int` | `int` |
| `double`、`num` | 数字：`int` 或 `float` |
| `DateTime` | 时间：一个 `Time`（std/time 的，即 `time.now()` 返回的值），或自 1970 年以来的纳秒数 |

如果没有指定类型，被 `plural`、`selectordinal` 或 `number` 计数的参数是 `int`，`date` 或 `time` 参数是 `DateTime`，其余参数都是 `String`。

如果源语言的目录里没有这个键，或者传入了文案不接受的参数、漏掉了文案需要的参数，又或者参数类型不对，都会在调用处报错：

```
app.asuka:8:13: locales/en.json has no message unred (did you mean tr.unread?)
app.asuka:9:10: tr.greeting needs its argument name (a string): its message is "Hello, {name}!"
```

## 文案

文案采用 ICU MessageFormat 格式，ARB 文件、Android 和 Format.JS 用的都是这种格式：

| 文案 | 显示 |
|---|---|
| `Hello, {name}!` | 在对应位置显示 `name` 的值 |
| `{count, plural, one {# file} other {# files}}` | 按文案所属语言中 `count` 的复数类别选择对应分支；`#` 表示这个数字 |
| `{count, plural, =0 {No files} one {# file} other {# files}}` | `=0` 只匹配恰好为 0 的情况，优先于复数类别 |
| `{n, plural, offset:1 =0 {Nobody} =1 {{host}} one {{host} and # other} other {{host} and # others}}` | 加上 `offset:1` 后，复数类别和 `#` 都按 `n - 1` 计算 |
| `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` | 序数类别：1st、22nd、103rd、11th |
| `{gender, select, female {She} male {He} other {They}} replied.` | 选择与值同名的分支，否则用 `other` |
| `{price, number}`、`{ratio, number, percent}`、`{n, number, integer}` | 按该语言的习惯书写数字（1,234.5；1.234,5；12,34,567） |
| `{price, number, ::.00}`、`{n, number, ::group-off}` | 固定保留两位小数，或者不加千位分隔符 |
| `{price, number, ::currency/EUR}` | 某种货币（用 ISO 4217 代码指定）的金额：货币符号放在该语言习惯的位置，小数位数按这种货币来（€1,234.50；1.234,50 €；¥1,235） |
| `{day, date, short}`、`{day, time, short}` | 按某种样式显示日期或时间：`short`、`medium`、`long` 或 `full` |
| `{day, date, ::yMMMd}` | 按 CLDR 骨架（skeleton）指定的字段显示日期，字段顺序遵循该语言的习惯（Jan 5, 2026；5. Jan. 2026） |
| `{day}`（`DateTime` 类型） | 按短样式显示它的日期和时间 |

分支可以嵌套，而且每个 `plural`、`selectordinal` 和 `select` 都必须有 `other` 分支。复数类别遵循 [Unicode CLDR](https://cldr.unicode.org) 中文案所属语言的规则：英语有 `one` 和 `other`，中文和日语只有 `other`，俄语有 `one`、`few`、`many` 和 `other`，阿拉伯语则有六种。

撇号用来转义紧随其后的花括号，在复数分支里也可以转义 `#`：`'{'` 显示为 `{`，两个连续的撇号显示为一个撇号。其他位置的撇号就是普通字符，所以 `don't` 无需转义。

## 在组件中使用

文案就是一个字符串，使用的是应用当前显示的语言。在绑定（prop 的值、`if` 的条件、`let`）里取出的文案，会像跟随参数那样跟随语言：语言切换时，每个取过文案的绑定都会重新取一次，除此之外什么都不会运行。因此，应用显示的所有文字都会跟着变化，无论是按钮、标签页或页面的标题，还是输入框的占位文字和视图的标签：

```asuka
import std/time

component Mailbox {
  state count = 3

  Column {
    Text(tr.inboxTitle()) { font: .largeTitle }
    Text(tr.greeting(name: "Ada"))
    Text(tr.unread(count: count))
    Text(tr.storage(used: 0.42))
    Text(tr.lastSeen(when: time.now()))
    Button(tr.markAllRead()) { on press { count = 0 } }
    TextField { placeholder: tr.greeting(name: "…") }
  }
}
```

取出文案的函数也一样：只要是在绑定里调用它，结果就会跟随语言变化：

```asuka
fn summary(count: int) -> string = if count > 0 { tr.unread(count: count) } else { tr.allRead() }

component Summary(count: int) {
  Text(summary(count))
}
```

在处理函数里取出的文案，就是取出那一刻的文字，之后不会再变。这正适合只显示一次、随后就消失的内容，比如警告框或通知。语言属于主线程，所以 `spawn` 里不能取文案：请先取出文案，再把字符串传进去。

## 应用显示的语言

应用同一时间只显示一种语言，可以通过 `i18n.locale()`（来自 std/i18n）获取。这种语言是这样选出来的：按照系统列出的用户首选语言顺序，在应用已有的语言中挑出用户最能读懂的那一种（比如读 `zh-TW` 的用户会看到 `zh-Hant`）；如果一种都匹配不上，就用应用的源语言。一个只有英文的应用，对读中文的用户显示的仍是英文，这一点和 UIKit 的行为一致。

用户的首选语言来自系统：

- **iOS 和 macOS**：“语言与地区”设置中的首选语言。
- **Android**：系统语言。
- **Windows**：用户的显示语言（“设置 > 时间和语言”）。
- **Linux**：会话的 `LANGUAGE`，没有的话依次取 `LC_ALL`、`LC_MESSAGES` 或 `LANG`。
- **Web**：浏览器的语言（`navigator.languages`）。

`i18n.setLocale("de")` 会立即切换到另一种语言，不需要重建任何东西：每个取过文案的绑定都会重新取一次，应用重新布局，屏幕上各个界面的状态都会保留。`i18n.setLocale("")` 则恢复跟随用户的语言。下面是一个列出应用所有语言的菜单，每种语言都用它自己的语言来显示名称：

```asuka
import std/i18n

component LanguageMenu {
  let choices = [""] + i18n.languages()

  List {
    for tag in choices key tag {
      Row {
        justify: .spaceBetween
        on press { i18n.setLocale(tag) }
        Text(if tag.isEmpty() { tr.systemLanguage() } else { i18n.autonym(tag) })
        if tag == i18n.locale() {
          Symbol("checkmark") { color: .accent }
        }
      }
    }
  }
}
```

`i18n.autonym` 返回一种语言在该语言中的名称（“Deutsch”“简体中文”“العربية”）。

用户的选择会在多次启动之间保留。在系统支持为单个应用设置语言的平台上，它会保存在系统里，从而也显示在系统设置中：

- **iOS 和 macOS**：保存在应用的 `AppleLanguages` 中，系统设置里为单个应用设置语言时写的就是它。UIKit 和 AppKit 自己的文字（比如日期选择器里的“取消”、Mac 的标准菜单）从下次启动起才会换成这种语言；你的文案则立即生效。
- **Android**：Android 13 及以上使用 `LocaleManager`，系统设置里能看到，系统自己的文字也会立即跟着切换；更早的版本则保存在 Asuka 的偏好设置里。
- **Windows 和 Linux** 没有单个应用的语言设置，因此保存在应用数据目录下的一个文件里。
- **Web**：保存在页面的 `localStorage` 中。

当用户在系统设置里更改了自己的语言或应用的语言时，应用会在运行中跟着切换（iOS 上则由系统重新启动应用）。

| std/i18n | |
|---|---|
| `locale()` | 当前显示的语言，是应用的语言标签之一 |
| `setLocale(tag)` | 切换到 `tag` 对应的语言，并保存这个选择；传 `""` 则恢复跟随用户的语言 |
| `languages()` | 应用支持的语言，源语言排在第一个 |
| `preferredLanguages()` | 用户能读懂的语言，最优先的排在最前面 |
| `isRTL()` | 应用是否从右到左布局 |
| `autonym(tag)` | 一种语言在该语言中的名称 |
| `region()` | 用户的区域格式：`locale`、`firstWeekday`（1 为星期日 …… 7 为星期六）、`hourCycle`（12 或 24） |
| `formatLocale()` | 当前显示的语言加上用户的区域格式：`en-GB-u-fw-mon-hc-h23` |
| `setLanguages(tags)` | 对于没有目录文件、自己负责翻译文字的应用：声明它是用哪些语言编写的，它自己的语言放在最前 |

在绑定里读取其中任何一个，结果都会跟随它所读取的内容变化。

## 选用哪条文案

对于请求的语言，会从最匹配的目录语言中取文案：`zh-TW` 匹配 `zh-Hant`，`pt-AO` 匹配 `pt-PT`，`en-AU` 匹配 `en-GB`。如果这种语言缺少某条文案，就沿着 CLDR 的父区域设置链回退（`en-AU` → `en-001` → `en`；`zh-Hant-HK` → `zh-Hant`），最后回退到源语言。也就是说，缺少翻译时会显示源语言的文案，而不是什么都不显示；不过其中的数字和日期仍按当前显示的语言书写。

## 数字与日期

文案会按当前显示语言的习惯书写其中的数字和日期；你自己要显示的数字和日期，则交给 std/i18n 来书写：

```asuka
import std/i18n
import std/time

component Stats(bytes: int, ratio: float) {
  Column {
    Text(i18n.formatNumber(1234567.891))              // 1,234,567.891; 1.234.567,891; 12,34,567.891
    Text(i18n.formatInt(bytes))                       // 1,234,567
    Text(i18n.formatPercent(ratio))                   // 25%; 25 %; ٢٥٪؜
    Text(i18n.formatCurrency("1234.5", "EUR"))         // €1,234.50; 1.234,50 €
    Text(i18n.formatDecimal("0.1234567890123"))        // 精确：0.1234567890123
    Text(i18n.formatNumber(2.5, minFractionDigits: 2)) // 2.50
    Text(i18n.formatDate(time.now(), date: .full))     // Monday, January 5, 2026
    Text(i18n.formatDate(time.now(), date: .short, time: .short)) // 1/5/26, 1:07 PM
    Text(i18n.formatRelative(time.now().add(-3h)))   // 3 hours ago; vor 3 Stunden
  }
}
```

`formatCurrency` 和 `formatDecimal` 接受按书写形式给出的数字，并且精确书写：[`std/decimal`](stdlib.md) 的 `Decimal` 调用 `formatted(currency:)`，就是对它的文本调用 `formatCurrency`。金额的小数位数按货币来（大多数是两位，日元没有小数，科威特第纳尔是三位），货币符号用该语言的写法（`$`、`US$`、`CHF`），并放在该语言习惯的位置。

这些数据来自 CLDR，与 ICU 和浏览器的 `Intl` 一致，并且只包含应用支持的语言：编译器会把每种目录语言的数字、分隔符、货币符号、格式模式，以及月份、星期和时段的名称放进应用，应用不支持的语言则一概不放。没有目录文件的应用按英语的习惯书写。

`formatRelative(t)` 以现在为参照来描述一个时间：“3 小时后”、“2 天前”；语言里有专门说法的会用那个词（“昨天”、“上周”），除非传了 `numeric: true`。`style:` 可以是 `.long`、`.short`（“3 小时前”的缩写形式）或 `.narrow`（最简短的形式）。它和 Apple 的 `RelativeDateTimeFormatter` 一样，按设备日历选出不为 0 的最大单位，并使用该语言的复数形式。在绑定里读取时，它跟随语言变化，而不会随时间自动更新：时间过去后需要重新显示。

日期按设备的时区、使用公历书写。UTC 以外的时区一律写成相对 GMT 的偏移量（`GMT+8`），即使 ICU 会为其中一些时区显示名称。无论是哪种语言，时间都遵循用户的小时制，也就是区域格式里的 12 小时制或 24 小时制（iOS 上是设置里的“24 小时制”）。在测试（`asuka test`）中，时区固定为 UTC，所以测试在每台电脑上看到的日期都一样。

## 从右到左

在从右到左书写的语言里，应用会自动从右侧开始布局，不需要你写任何代码：`Row` 从右侧开始排列，`justify` 和 `align` 也随之从右侧算起，文字从右边开始，平台自己的视图也会镜像翻转（导航栏及其返回手势、标签栏、push 和 pop 动画、滑块、列表的滑动操作）。横向的 `Scroll` 从最右端开始。应用运行时切换到这类语言，或者从这类语言切换出去，都会立即重新布局。布局遵循 CSS 的 `direction`，并与 Chrome 的结果做过比对。

需要你手动摆放的内容：

```asuka
component Card {
  View {
    padding: Edges(start: 16)       // 放在文字开始的一侧
    Text(tr.greeting(name: "Ada"))
    Symbol("chevron.forward") { absolute: true; end: 8 }   // 从文字结束的一侧算起
  }
}
```

`left` 和 `right`（无论是 `Edges` 里的，还是配合 `absolute` 使用的）与 CSS 一样，说左就是左、说右就是右。需要镜像的地方请用 `start` 和 `end`，而几乎所有地方都应该镜像。

名称里用 `forward` 或 `backward` 表示方向的图标会镜像：`chevron.forward`、`arrow.backward`。`chevron.left` 则不会，适合那些在任何语言里都朝左的东西（比如媒体播放器的快退按钮）。

一行文字的方向由它自身的字符决定：阿拉伯语应用里的一句英文会靠右放置，句号仍然在句子末尾。这行文字靠哪一侧由应用决定，字符的顺序则由 Unicode 双向算法决定。从右到左语言的文案如果以拉丁字母写的名字或数字开头，Asuka 会在它开头加上一个从右到左标记（right-to-left mark），让它仍然从右侧读起。

对于在任何语言里都按同一方向阅读的内容，比如电话号码、媒体播放器的控制按钮或代码编辑器，需要显式声明：

```asuka
component Controls {
  Row {
    layoutDirection: .leftToRight
    Button(tr.previous()) { icon: "backward.fill" }
    Button(tr.play()) { icon: "play.fill" }
    Button(tr.next()) { icon: "forward.fill" }
  }
}
```

对于不会自动跟随方向的内容（比如自己绘制的图形），可以用 `i18n.isRTL()` 判断应用当前的方向。视图的 frame、`on layout` 和 `on scroll` 都使用物理坐标，从左边算起。

## 试用一种语言

```sh
asuka dev --platform ios --lang de .       # 本次运行以德语显示应用
asuka dev --platform ios --lang en-XA .    # [Šéļéçţ ƒîļéš one two]
asuka dev --platform ios --lang ar-XB .    # 每个单词从右到左，布局也一样
asuka dev --platform ios --dir rtl .       # 让任意应用从右到左显示，无需翻译
```

`--lang` 和 `--dir` 适用于 `asuka dev` 支持的所有平台：它们会被编进开发 App 运行的内容里，所以无论用户平时读哪种语言，iOS 模拟器、手机、Android 模拟器、桌面端和浏览器显示的效果都一样；而且只要指定了这两个参数，`setLocale` 就不会保存任何选择：

```sh
asuka dev --lang ar .                      # 在本机运行：macOS、Windows 或 Linux
asuka dev --platform web --dir rtl .       # 在浏览器中运行
```

这两个伪区域设置（pseudo locale）可以在还没有任何译文时就测试布局，和 Android 的做法一样。`en-XA` 会给源语言文案的字母加上变音符号，把文字拉长三分之一，并用方括号括起来：如果某段文字没有变化，说明它不在目录里；如果文字被截断，说明给它的空间太小；如果一句话里出现好几对方括号，说明它是由几个片段拼出来的，翻译时无法调整语序。`ar-XB` 则能暴露出哪些地方没有镜像。它们都不需要目录文件。手动启动开发 App 时，设置 `ASUKA_LOCALE=de` 和 `ASUKA_DIRECTION=rtl` 也有同样的效果。

## 检查目录文件

`asuka dev`、`asuka build` 和 `asuka i18n check` 都会检查目录文件，编译器会指出问题出在哪个目录文件的哪一行。出现错误时它们会停止：

- 文件名不是规范的语言标签，或者与其中的 `@@locale` 不一致；
- 文案无法解析；
- 译文里有源语言没有的键，或者使用了 Asuka 中不存在的 `asuka.<key>` 键；
- 译文使用了源语言文案中没有的参数，或者参数的用法与其类型不符（比如用 `plural` 计数一个 `String`）。

警告则不会让它们停止，包括：译文缺少某些文案（会显示源语言的文案）；译文漏掉了某些参数；出现了该语言没有的复数分支（比如英语里的 `few`），或者缺少该语言需要的复数分支（比如俄语里的 `few`，缺少时会用 `other` 代替）；占位符没有在文案中使用。

## 系统显示的内容

`asuka build` 会声明目录文件中的语言（iOS 和 macOS 上是 `CFBundleLocalizations` 和若干 `.lproj`，Android 上是 `locales_config`）。正是这些声明，让 iOS 和 macOS 能用这些语言显示系统自己的文字，并在设置中提供应用的语言选项。Windows 和 Linux 没有单个应用的语言设置：只有 Windows 的 MSIX 会声明这些语言（Microsoft Store 据此列出应用支持的语言），Windows 的安装程序则会用用户语言中的 `asuka.appName` 来称呼应用（见[打包与发布](shipping.md#windows)）。目录文件中的 `asuka.<name>` 键用于翻译构建时写入这些地方的内容：

```json
{
  "asuka.appName": "Notizen",
  "asuka.NSCameraUsageDescription": "Um Belege zu scannen.",
  "asuka.widget.steps.name": "Schritte",
  "asuka.widget.steps.description": "Deine Schritte heute.",
  "asuka.shortcut.newNote": "Neue Notiz"
}
```

## Asuka 自带的文字

Asuka 自己显示的文字很少，因为大部分文字由平台提供。它们包括：警告框里唯一的那个按钮、搜索框的占位文字、桌面端的“返回”、Mac 上的“关于”“隐藏”和“退出”，以及步进器的标签。Asuka 会用应用当前显示的语言来显示这些文字，它们已经翻译成常用语言。你的目录文件里的 `asuka.<key>` 键会对照这些文字来检查；不过 Asuka 目前还不会显示应用自己提供的版本。
