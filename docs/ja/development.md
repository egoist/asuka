# 開発

`asuka dev` はアプリを実行し、ファイルを保存するたびにリロードします。実行先は、iOS シミュレーターか iPhone、Android のエミュレーターか実機、手元の Mac・PC・Linux マシン、ブラウザーのいずれかです。このページでは、`asuka dev` が動かす開発用アプリ、リロードで何が保たれるか、デバイス、アセット、ログ、プレビュー、エディター、よくある問題について説明します。デバイスやディスプレイなしでアプリの UI をテストするには、[テスト](testing.md)を参照してください。

## asuka dev

```sh
asuka dev [flags] [dir]                     # このコンピューター：macOS、Windows、Linux
asuka dev --platform ios [flags] [dir]       # iOS シミュレーター
asuka dev --platform ios --device iphone [dir]  # 接続している iPhone（または iPad）
asuka dev --platform android [flags] [dir]   # Android のエミュレーターまたは実機
asuka dev --platform ios,android [dir]       # 両方のスマートフォンで同時に
asuka dev --platform web [flags] [dir]       # ブラウザー
```

`--platform` には `ios`、`android`、`mac`、`windows`、`linux`、`web` のいずれかを指定します。`asuka build` でも同じように使えます。省略すると、今使っているコンピューター向けにアプリを実行（またはビルド）します。`ios,android` を指定すると、起動中の iOS シミュレーターと最初の Android 実機またはエミュレーターで同時にアプリを実行します。保存するたびに両方がそれぞれのプラットフォーム向けのビルドで再読み込みされ、設定、アセット、ネイティブコードを変更すると両方が起動し直します。それ以外の組み合わせでは、ターミナルを二つ開いてください。実行されるのは開発ビルドで、[`@debug`](language/control-flow.md#開発ビルド向けのコード) は true です。

`dir` はアプリのディレクトリで、デフォルトはカレントディレクトリです。ここにはアプリの `.asuka` ファイル（そのうち一つに `app` ブロックがあります）と `asuka.toml` を置きます。フラグは次のとおりです。

- `--platform`：上で説明したとおりです。
- `--lang`：この実行でだけ表示する言語（`de`、`zh-Hans`）か、疑似ロケールを指定します。疑似ロケールは `en-XA`（アクセント記号付きで長めのテキスト）と `ar-XB`（右から左）です。`--dir rtl` を付けると、どのアプリでも右から左にレイアウトします。[多言語対応](i18n.md)を参照してください。
- `--once`：アプリを一度だけ起動し、ファイルの監視はしません。
- `--debug-port`：エディターのデバッガーが接続するポートです（[デバッガー](#デバッガー)を参照）。
- `-v`：Asuka が実行するコマンドを表示します。

スマートフォンでは、次のフラグも使えます。

- `--device`：iOS ではシミュレーターの名前か UDID（デフォルトは起動中の iPhone で、なければ最近の iPhone Pro を起動して使います）、接続している iPhone か iPad の名前か UDID、または接続している 1 台を表す `iphone` を指定します（[デバイス](#デバイス)を参照）。Android では adb のシリアル番号か AVD の名前を指定します（デフォルトは adb が最初に挙げるデバイスで、なければ最初の AVD を起動して使います）。
- `--team`：iPhone で実行するときに、開発用アプリに署名する Apple Developer のチームを指定します。

ブラウザーでは `--port`、`--lan`（スマートフォンのブラウザーから使えるよう、ネットワーク上に配信します）、`--no-open` が使えます。[Web](web.md#asuka-dev---platform-web) を参照してください。

実行中は、ターミナルでキーを押して操作できます。**r** でアプリを最初からやり直し（[リロードで保たれるもの](#リロードで保たれるもの)）、**i** で[インスペクター](#インスペクター)を開き、**v** でアプリの[プレビュー](#プレビュー)を一覧します（数字で一つを表示し、**0** でアプリに戻ります）。**p** は[パフォーマンスのオーバーレイ](#オーバーレイ)を表示し、**t** は[プロファイルを記録](#プロファイルを記録する)し、Ctrl-C で終了します。

## 開発用アプリ

開発中、アプリは**開発用アプリ**の中で動きます。これはアプリの外側（名前、ID、アイコン、`Info.plist` またはマニフェスト、ネイティブパッケージのコード）で、`asuka dev` がプラットフォームごとに一度だけビルドし、インストールして起動します。そこへ `asuka dev` があなたのアプリを送ります。保存するたびにコンパイルし直し（数ミリ秒です）、新しいバージョンを送ります。開発用アプリはそれをその場で読み込み、アプリの状態を保ったまま、結果を報告します。

```
asuka: compiled in 3.1 ms
asuka: reloaded in 2.2 ms, 4 states kept
```

保存した内容がコンパイルできない場合は、エラーが `file:line:col: message` の形でターミナルに表示され、アプリの上にも表示されます（[アプリに重なるエラー表示](#アプリに重なるエラー表示)を参照）。開発用アプリはそれまでのバージョンを実行し続け、次にコンパイルできたときに、そこから続きます。アプリのそれ以外の部分（`asuka.toml`、アセット、ネイティブパッケージの Swift・Kotlin・JavaScript）が変わると、開発用アプリをビルドし直し、変わっていれば再インストールしてから起動します。

## デスクトップでの実行

macOS、Windows、Linux では、`asuka dev` は開発用アプリをウィンドウで実行します。初回の実行では、このコンピューター向けに開発用アプリをビルドするので少し時間がかかります。2 回目以降はすぐに起動します。ビルドには C コンパイラーが必要です。Mac では Xcode のコマンドラインツール、Windows と Linux では Zig、clang、gcc のいずれか（`ASUKA_CC` で選べます）です。

アプリは `assets/` をその場所から直接読むので、アセットを変更してもコピーは必要ありません。アプリのデータ（SQLite データベース、ファイル）は、インストールしたアプリのデータとは別に、Asuka のキャッシュ内にあるアプリ専用の `data` ディレクトリに保存されます（[最初からやり直す](#よくある問題)を参照）。そのため、`asuka dev` とリリース版がデータを共有することはありません。アプリの出力とエラーはターミナルに表示されます。

**macOS。** 開発用アプリは、リリース版と同じ形の `.app` として Asuka のキャッシュ内に置かれます。この `.app` には、`Info.plist`（`asuka.toml` の名前、bundle ID、URL スキーム、利用目的の説明文、言語）とアイコンが含まれ、アドホック署名されます。そのため、Finder から開いたときと同じく、システムからはそのアプリ自身として扱われます。Dock にはアプリの名前とアイコンが表示され、通知もアプリ自身のものになり、プライバシーに関する許可の確認（カメラ、位置情報、連絡先）もターミナルではなくアプリに対して、アプリの利用目的の説明文とともに表示されます。プロビジョニングプロファイルのエンタイトルメントが必要なパッケージ（プッシュ通知、Sign in with Apple、App Attest）は、そのプロファイルで署名したリリースビルドでしか動きません。[配布](shipping.md#macos)を参照してください。

**Windows。** `asuka dev` は Windows 上でしか動きません。一方、`asuka build --platform windows` はどのシステムからでも（Zig で）ビルドでき、アプリを含む 1 つの `.exe` ができます。開発用アプリはコンソールプログラムなので、出力はターミナルに表示されます。リリース版にはコンソールがありません。

**Linux。** Linux では、`asuka dev` は GTK 4 と libadwaita の上で開発用アプリを実行します。これらがインストールされている必要があります（[はじめに](getting-started.md#必要なもの)を参照）。アプリは、セッションのディスプレイ（Wayland または X11）で動きます。Mac や PC で `asuka dev --platform linux` を実行できるのは、`ASUKA_LINUX_RUN` に、ディスプレイのある Linux マシンでプログラムを実行するコマンドを指定した場合だけです。そのマシンからは、このコンピューターのファイルが同じパスで見える必要があります。たとえば VM で、`ASUKA_LINUX_RUN="orb -m ubuntu"`（OrbStack）や `ASUKA_LINUX_RUN="limactl shell default"`（Lima）のように指定します。Asuka はそのマシンのアーキテクチャー向けに開発用アプリをビルドし（Zig が必要です）、開発用アプリはネットワーク経由で `asuka dev` に接続します。接続先は、このコンピューターの最初のアドレスか、`ASUKA_DEV_HOST` に指定したアドレスです。

## リロードで保たれるもの

どのプラットフォームでも、リロードではアプリのすべての `state` が保たれます。そのためのコードを書く必要はありません。状態の各セルは、そのコンポーネントのビューツリー上の位置と、セルの名前で保存されます（`Inbox.query` なら、それを表示している画面と行の下）。新しいモジュールで同じ位置、同じ名前にあるセルは、その値から始まります。値はフィールド名とケース名をもとに、新しいモジュールの型に変換されます。追加したフィールドはデフォルト値から始まり、削除したフィールドは捨てられます。変換できない形で型が変わった状態（`int` が `string` になったなど）は、初期値からやり直しになります。ビューは新しいモジュールから作り直され、それまでの状態を表示します。画面は変更を反映しつつ、前と同じように見えます。

次のものは保たれません。

- 初期値を書き換えた状態は、新しい初期値から始まります（`state count = 0` を `state count = 10` にした場合など）。ほかの状態はそれぞれの値を保ちます。初期値の書き方（空白や改行）を変えただけなら、書き換えたことにはなりません。
- 名前を変えた状態や、別のコンポーネントに移した状態は、最初からやり直しになります。コンポーネント自体をビューツリーの別の位置に移した場合も同じです。
- `let` の値は保たれません。読んでいるものから計算し直されます。
- タスクとエフェクトは、新しいモジュールで始め直されます（保存した時点で実行中の `task` はキャンセルされ、新しいものが実行されます）。

アプリを最初からやり直すには、`asuka dev` を実行しているターミナルで **r** を押します。どの開発用アプリも状態を何も保たずにアプリを読み込み直し、すべての `state` が起動したときと同じく初期値から始まります。開発用アプリ自体は起動し直しません（`asuka: restarted in 2.0 ms`）。`asuka dev` を止めて実行し直しても、アプリは何もない状態から始まります。どちらの場合も、アプリが書き込んだファイル（SQLite データベース、ファイル）は残ります。これらはアプリのデータディレクトリ、つまりデバイス上か、デスクトップなら Asuka のキャッシュ内にあります。

## アプリに重なるエラー表示

開発中に起きた問題は、ターミナルだけでなく、デバイスやウィンドウ上でもアプリに重ねて表示されます。

- **どこでも捕捉されなかったエラー**：`Boundary` に囲まれていないハンドラー、エフェクト、タスクが投げたエラーや、アプリの `init` が投げたエラーです。オーバーレイには、エラーメッセージ、それが投げられたソースの該当行、そこに至るまでの呼び出し（内側から順に）が表示されます。
- **コンパイルできなかった保存**：最初のエラー、その位置のソース（問題の部分に `^` の印）、エラーの解説ページ、残りのエラーが表示されます。コンパイルできる保存があれば自動で消えます。また、アプリ自身のエラーより優先して表示されます。アプリのエラーは、いま書き換えている途中のコードから出たものだからです。

**Dismiss**（または Escape、Android の戻る操作）で、アプリは元の状態に戻ります。エラーを投げたハンドラーやエフェクトはそこで止まりましたが、それ以外はそのまま動き続けます。アプリ自身のエラーには **Reload** もあり、**r** と同じようにアプリを最初からやり直し、すべての `state` が初期値に戻ります。表示中にさらにエラーが起きた場合は、最初のエラーを表示したまま、そのあといくつ起きたかを示します。残りのエラーはたいてい最初のエラーが原因だからです。コンパイルできる保存があると、古いコードから出たアプリのエラーは消えます。

オーバーレイは各プラットフォーム自身のビューで描かれ、アプリの画面、シート、アラートの上に重なります。そのため、壊れているのがアプリ自身のビューであっても表示されます。表示されるのは `asuka dev` の中だけです。ビルドしたアプリでは、捕捉されなかったエラーはログに記録されるだけで、ユーザーにエラーを見せるには `Boundary` を使います。

## リロード

Asuka は、アプリのディレクトリとそのローカルの依存関係（`asuka.toml` の `file:`）のディレクトリを監視し、次の変更を検知します。

- `.asuka` ファイル：コンパイルして、その場でリロードします。
- `asuka.toml` と `asuka.lock`、`assets/` 以下のファイル、言語のカタログ、ネイティブパッケージの Swift・Kotlin・JavaScript、`Info.plist` とエンタイトルメント：開発用アプリをビルドし直して起動します（アプリは何もない状態から始まります）。

`.` で始まるディレクトリと、`testdata`、`build`、`dist`、`node_modules` は監視の対象外です。

## デバイス

**手元のコンピューター**：Mac、PC、Linux で、`asuka dev` を何も指定せずに実行します。

**iOS シミュレーター**は Mac とネットワークを共有するので、特に設定はいりません。

**Android のエミュレーターや実機**：`asuka dev` は、エミュレーターにも USB で接続した実機にも adb 経由で接続します。実機の場合は、開発者向けオプションで USB デバッグを有効にし、ケーブルで接続して確認ダイアログで許可したら、`adb devices` に表示されることを確かめます。`asuka dev --platform android` は、実機かエミュレーターかを問わず、adb が最初に挙げるデバイスを使います。複数ある場合は、`--device` にシリアル番号を指定して選んでください。

**iPhone**（または iPad）では Xcode 26 以降が必要です。iPhone をケーブルで接続してロックを解除し、「信頼」をタップします。次に「設定」›「プライバシーとセキュリティ」で「デベロッパモード」をオンにします（iPhone が一度 Xcode に接続されると表示されます。オンにすると iPhone が再起動します）。あとは `asuka dev --platform ios --device iphone` で実行できます。複数台つないでいる場合は、`--device` に名前か UDID を指定します（一覧は `xcrun devicectl list devices` で確認できます）。

- **署名**：開発用アプリは、あなたのチームの開発用証明書で署名されます。チームは `--team`、`ASUKA_TEAM_ID`、`asuka.toml` の `ios.team` の順に探し、どれもなければキーチェーンにある Apple Development 証明書のチームを使います。初回の実行では、必要な開発用プロビジョニングプロファイルを Xcode に作らせます。このとき iPhone がチームに登録され、アプリが使うケイパビリティ（プッシュ通知、App Groups など）が有効になります。使われるのは Xcode の「設定」›「アカウント」の Apple ID か、`ASUKA_ASC_KEY_ID`（または `ios.appStoreConnect`）で指定した [App Store Connect API キー](shipping.md)です。チームの既存のプロファイルが合うなら（ワイルドカードのものも含め）、そのまま使います。
- **Mac への接続**：ケーブルでつないでいれば、Xcode と同じように、Mac がケーブル経由で開発用アプリに接続します。iPhone はどのネットワークにもつながっている必要がありません。ケーブルがないときは、開発用アプリがネットワーク経由で `asuka dev` に接続します。Mac のアドレス（または `ASUKA_DEV_HOST` のアドレス）を順に試し、ポートは空いていれば 8791 です。iOS は一度だけ、このアプリがネットワーク上のデバイスを探してよいかを尋ねるので、許可してください（あとから「設定」›「アプリ」›「ローカルネットワーク」でもオンにできます）。どちらの場合も、`asuka dev` が起動し直せば開発用アプリは自動でつなぎ直し、ホーム画面から開き直しても `asuka dev` を見つけられます。開発用アプリが接続できない場合は、何を確かめればよいかを Asuka が表示します。

**テレビ**：`asuka dev --platform tvos` は Apple TV シミュレーターで、`asuka dev --platform android --device <名前>` は Android TV のエミュレーターか adb でつながるテレビでアプリを動かします。[テレビ](tv.md)を参照してください。

**ウォッチ**：`asuka dev --platform watchos` は Apple Watch のシミュレーターでアプリを動かします。[Apple Watch](watch.md) を参照してください。

**スマートフォンのブラウザー**：`asuka dev --platform web --lan` でアプリをネットワーク上に配信すると、開くべきアドレスが表示されます。最初のアドレスは QR コードでも表示されるので、スマートフォンのカメラで読み取れます。

## アセット

デスクトップでは、開発用アプリは `assets/` をその場で読みます。スマートフォンでは、アセットは変更があったときに開発用アプリへコピーされます。ブラウザーでは、開発サーバーがアセットを配信します。アセットを変更すると、開発用アプリがビルドし直されて起動します。

## ログ

開発用アプリは自身の出力とエラーを `asuka dev` に送り、`asuka dev` がそれをターミナルに表示します。どのプラットフォームでも、`print`、捕捉されなかったエラー（そこに至るまでの呼び出しも含みます。アプリの上にも表示されます。[アプリに重なるエラー表示](#アプリに重なるエラー表示)を参照）、Asuka 自身の警告とエラーが表示されます。開発用アプリがモジュールを読み込めなかった場合は、その理由が表示されます（`asuka: the player: ...`）。ブラウザーでは、ページのエラーもターミナルに表示されます。

## インスペクター

`asuka dev` はインスペクターのアドレスを表示します。

```
asuka: the inspector (the app's views): http://127.0.0.1:52817/
```

同じコンピューターのブラウザーで開く（または `asuka dev` を実行しているターミナルで **i** を押す）と、実行中のアプリのビューがツリーで表示されます。それぞれのビューの要素、テキスト、親ビューの中での frame がわかります。ビューにポインターを合わせるかクリックすると、アプリがデバイス上でそのビューをハイライトします。クリックすると詳細も表示され、Escape で選択を解除します。不要な部分は折りたたみ、要素やテキストで絞り込むこともできます。ツリーは毎秒アプリに追従します（止めておきたいときは Live をオフにします）。複数のデバイスが接続されているとき（iPhone とエミュレーターなど）は、上部で一つを選びます。シート、ポップオーバー、ほかのウィンドウはそれぞれ別のツリーとしてアプリのツリーの後に並び、リストのセルはリストの子として表示されます。

ほかに **Performance** タブ（[パフォーマンス](#パフォーマンス)）と **Previews** タブがあります。**Previews** タブにはアプリのプレビューが並び、選んだものをアプリの代わりにデバイスに表示できます（[プレビュー](#プレビュー)）。

## プレビュー

プレビューは、コンポーネントを単独で、見たい状態と設定で表示するものです。コンポーネントを作るコードのすぐそばに書けます。SwiftUI の `#Preview`、Flutter の widget previewer、Storybook に当たる Asuka の機能で、アプリやパッケージのどの `.asuka` ファイルにも `preview` ブロックとして書けます。

```asuka
preview "Counter" { Counter() }

preview "Dark, large text" (dark: true, fontScale: 1.5) { Counter() }

preview "Right to left, small" (rtl: true, width: 320, height: 240) { Counter() }
```

本体はコンポーネントと同じビューの本体で（独自の `state` を持てますし、使うストアを `provide` できます）、設定で表示のしかたを決めます。ダークかライトか、文字の大きさ、言語と書字方向、フレームのサイズです。詳しくは言語リファレンスの[プレビュー](language/components.md#プレビュー)を参照してください。

`asuka dev` は、アプリを実行しているデバイスに、アプリの代わりにプレビューを表示します。ターミナルで **v** を押すと、アプリのプレビューが番号付きで、それぞれの設定と書かれている場所とともに一覧表示されます。

```
asuka: the app's previews (press a number to show one, 0: the app):
  1  Counter  app.asuka:38
  2  Dark, large text (dark: true, fontScale: 1.5)  app.asuka:40
  3  Right to left, small (rtl: true, width: 320, height: 240)  app.asuka:42
```

1 から 9 の数字を押すと、その番号のプレビューがすべてのデバイスに表示されます。**0** か Escape でアプリに戻ります。インスペクター（[インスペクター](#インスペクター)）の **Previews** タブにも同じ一覧があり、クリックするとそのプレビューを表示し、**Show the app**（または Escape）でアプリに戻ります。複数のデバイスが接続されているときは、**On every device**（デフォルトでオン）がオンならすべてのデバイスに、オフなら上部のメニューで選んだデバイスにだけ表示します。

デバイスはプレビューの設定を反映して表示します。ダークかライトか、文字の大きさ、言語と書字方向が設定どおりになり、`width` か `height` があれば、そのサイズのフレームでウィンドウの中央にレイアウトされます。保存するたびに、アプリと同じようにリロードされ、状態は保たれます（[リロードで保たれるもの](#リロードで保たれるもの)）。プレビューの名前を変えても表示は続き、削除するとアプリに戻ります。アプリに戻ったとき、アプリの状態はプレビューを表示する前のままです。すべてのデバイスにプレビューを表示している間に接続したデバイスにも、そのプレビューが表示されます。Web ではページがプレビューを表示します。

エディターでは、各プレビューブロックの上に **▶ Preview** が表示されます。クリックすると、そのファイルのアプリを実行している `asuka dev` が、デバイスにそのプレビューを表示します（[エディター](#エディター)）。`asuka dev` が動いていなければ、アプリのディレクトリで起動するようエディターが案内します。

プレビューはビルドには含まれません。`asuka build` にも `asuka dev` が実行するアプリにもプレビューはなく、プレビューだけが使うものも含まれません。`asuka test --previews` は各プレビューをテストとして実行し、表示内容をスナップショットと比べます。つまり、普段見ているプレビューがそのまま回帰テストにもなります（[プレビューをテストとして使う](testing.md#プレビューをテストとして使う)）。

## デバッガー

`asuka dev` にはデバッガーがあります。`.asuka` ファイルにブレークポイントを置くと、アプリが動いているデバイス（シミュレーター、iPhone、Android のエミュレーターや実機、手元の Mac、PC、Linux マシン）の上で、アプリはそこで止まります。エディターには、そこに至るまでの呼び出しとそれぞれの変数が表示され、そこからステップ実行できます。エディターは Debug Adapter Protocol（DAP）で、`asuka dev` が表示するアドレスに接続します。

```
asuka: the debugger (an editor's, by DAP): 127.0.0.1:8791
```

ポートは 8791 です。ほかの `asuka dev` がすでに使っていれば空いているポートになり、`--debug-port` で指定することもできます。

**VS Code** では、`editors/vscode` の拡張機能（[エディター](#エディター)を参照）が `launch.json` に二つの構成を追加します。**Asuka: Run and Debug** はアプリの `asuka dev` をターミナルで実行し、アプリが動き出したら接続します。`platform`、`device`、`args` でどこでどう動かすかを指定でき、デバッグを止めると `asuka dev` も止まります。**Asuka: Attach to asuka dev** は、自分で起動した `asuka dev` にその `port` で接続します。`launch.json` がなければ、`.asuka` ファイルで F5 を押すと、ワークスペースのアプリをこのコンピューターで実行してデバッグします。

```json
{
  "version": "0.2.0",
  "configurations": [
    { "type": "asuka", "request": "launch", "name": "Asuka: Run and Debug", "app": "${workspaceFolder}", "platform": "ios" },
    { "type": "asuka", "request": "attach", "name": "Asuka: Attach to asuka dev", "port": 8791 }
  ]
}
```

**ほかのエディター**でも、その DAP クライアントがアドレスを指定してデバッグアダプター（TCP ポートで待ち受けるサーバー）に接続できるなら、同じポートに `attach` リクエストで接続できます（`launch` も同じで、動いている `asuka dev` に接続します）。Neovim の nvim-dap なら次のとおりです。

```lua
local dap = require("dap")
dap.adapters.asuka = { type = "server", host = "127.0.0.1", port = 8791 }
dap.configurations.asuka = {
  { type = "asuka", request = "attach", name = "Attach to asuka dev" },
}
```

できること：

- **ブレークポイント**は行単位で、アプリのファイルにも、アプリが使うパッケージのファイルにも置けます。コードのない行に置いたものは、エディターに表示されるとおり、次にコードのある行へ移ります。保存しても、アプリが起動し直しても残ります。アプリがまだ使っていないファイルに置いたものは、使われるようになった時点で有効になります。
- **条件、ヒット回数、ログポイント。** ブレークポイントの条件は Asuka の式（`todo.done && count > 3`）で、その行に書くコードと同じように書けます。そのフレームの名前、ファイルがインポートしたもの、コンポーネントのメンバーが使えます。条件が成り立つときだけ止まります。ヒット回数は、条件が成り立った回だけを数えて、何回目で止まるかを決めます：`5`（5 回目）、`>= 5`、`> 5`、`<= 5`、`< 5`、`% 5`（5 回ごと）。ログポイントは止まらず、メッセージをデバッグコンソールに書き出します。メッセージ中の `{式}` は、文字列の埋め込みと同じようにその値に置き換わります（`count is {count}`）。コンパイルできない条件は、その理由がブレークポイントに表示されます。実行中にエラーを投げた条件は、そこで止まって理由を伝えます。
- **エラー。** エディターのブレークポイント一覧で **Uncaught Errors**（最初からオン）を選ぶと、アプリのどこにも捕まえられないエラーが投げられたとき、何も巻き戻される前に、投げられた場所で止まります。コールスタックと変数は `throw` の時点、あるいは失敗した呼び出しや演算（`a / 0`、範囲外の添字）の時点のままです。エラーを捕まえるのは、外側の `catch`、`try?`、式の後ろの `catch`、コンポーネントを囲む `Boundary`、そしてエラーが投げられたタスクを待っているコードです。`defer` は実行されたあとエラーをそのまま投げ直すので、捕まえたことにはなりません。**All Errors** は、捕まえられるかどうかに関係なく、すべてのエラーで止まります。エディターにはエラーの型とメッセージが表示されます。
- **止まった場所**：コールスタックと、各フレームの変数（引数、`let` と `var`、`self`、コンポーネントの `state` の現在の値）が、Asuka での書き方のまま表示されます。構造体のフィールド、列挙型の関連値、配列・マップ・セットの要素は展開して見られます。
- **式の評価**：一時停止中に、見ているフレームで式を評価できます。名前へのホバー、ウォッチビュー、デバッグコンソールから使えます。式はその行のコードと同じようにコンパイルされてデバイスの上で実行され、結果は変数と同じ形で表示され、中身も展開できます。これはアプリのコードそのものです。呼び出したもの（関数やストアのメソッド）は実際に動き、その結果も残ります（書き込んだ state は変わり、アプリが再開すると画面に反映されます）。評価中はブレークポイントでもエラーでも止まりません。フレームの変数への代入は式ではないので、この方法で値を変えることはできません。式の中で `await` は使えません。
- **続行、ステップオーバー、ステップイン、ステップアウト、一時停止。** 一時停止すると、アプリが次にコードを実行したとき（タップやタイマー）に止まります。何もしていないアプリはコードを実行しません。
- **デバイスごとに一つのスレッド**：`asuka dev --platform ios,android` では、iPhone とエミュレーターがそれぞれ別々に止まり、別々に再開します。
- アプリの出力はエディターのデバッグコンソールに表示されます。
- 一時停止中に保存すると、アプリは再開し、読み込んだ新しいコードでもブレークポイントで止まります。ブレークポイントの条件とログポイントも新しいコードに合わせてコンパイルし直されます。

一時停止中は、Xcode や Android Studio のデバッガーと同じように、アプリのメインスレッドが待機しています。アプリは描画もタッチへの応答もせず、デスクトップの OS はウィンドウが応答していないと表示することがあります。Android では `asuka dev` がアプリをデバッグ中のアプリとして起動するので、この一時停止が応答なしとして扱われることはありません。

まだできないこと：

- エディターから変数の値を変えること。
- アプリ自身のコードでは一度もそうしていないのに、アプリの型をあるインターフェースの値として使う式（アプリで `Circle` が `Shape` として使われていないのに `let s: Shape = circle` を評価するなど）：デバッガーはその旨を伝えます。
- Web（`--platform web`）：アプリの一時停止中に、ページはメインスレッドで待機できません。
- `spawn` がワーカーで実行するコードは止まりません。
- 一時停止中、デバイスには何も表示されません。表示されるのはエディターだけです。
- 接続できるエディターは一度に一つです。後から接続したものが引き継ぎます。

デバッガーがあるのは開発ビルドだけで、リリースビルドにはありません。

## パフォーマンス

`asuka dev` では、アプリを操作しながらその速さを確かめられます。すべてのプラットフォームで使えるのは、アプリに重ねて表示するパフォーマンスオーバーレイと、操作の前後で記録してインスペクター、Perfetto、speedscope で読むプロファイルです。

アプリの仕事は**フラッシュ**という単位で進みます。何かが起きる（タップ、タイマー、task の完了、リストが新しい行を表示する）と、アプリのコードが動き（まずイベントハンドラー、次にその変更を読んでいる effect とバインディング）、Asuka が変わったものをまとめてプラットフォームに渡します。フラッシュには五つのフェーズがあります。

- **App**：アプリのコード。イベントハンドラー、effect、task と、それらのために Asuka が行う処理。
- **Props**：プラットフォームが変更を反映する（テキスト、色、作られるビューと取り除かれるビュー）。
- **Layout**：ビューのレイアウト。テキストやコントロールの大きさはプラットフォームが測ります。
- **Frames**：プラットフォームがビューを新しい frame に動かす。
- **After**：`on layout` ハンドラーと、それが引き起こす変更。

アプリが忙しくてディスプレイが描けなかったフレームが**ドロップしたフレーム**です。画面には同じ絵が二度表示され、アニメーションやスクロールがカクつきます。毎秒 60 フレームなら 1 フレームは 16.7 ms、120 フレームなら 8.3 ms です。

### オーバーレイ

`asuka dev` を実行しているターミナルで **p** を押すと、アプリが動いているすべてのデバイスにオーバーレイが表示されます（もう一度押すと消えます）。インスペクターの **Performance** タブで、デバイスごとにオンにすることもできます。アプリの上部に出る小さなボックスで、画面やシートの上に重なり、タップは下のアプリにそのまま届きます。

```
UI 60 fps · dropped 0 · 4 flushes/s
last 1.8 ms: app 0.9 props 0.3 layout 0.4 frames 0.2
worst 6.1 ms · 42 ops · 7 effects · 3 measures
memory 31.2 MB · 1.2k allocs/s · 120 views
```

- **UI fps**：直近 1 秒間にディスプレイが描いたフレーム数と、直近 5 秒間に**ドロップした**（dropped）フレーム数。
- **flushes/s**：直近 1 秒間に走ったフラッシュの数（何もしていないアプリでは 0）。
- **last**：最後のフラッシュにかかった時間をフェーズごとに（frames には after も含みます）。
- **worst**：直近 5 秒間でいちばん遅かったフラッシュ。
- **ops、effects、measures**：最後のフラッシュの仕事量。プラットフォームに送った変更、走った effect とバインディング、プラットフォームが測ったテキストとコントロールの数です。
- **memory**：アプリのメモリ。**allocs/s**：1 秒あたりのメモリ確保の回数。**views**：アプリが持つプラットフォームのビューの数。

表示は 1 秒に 2 回更新され、リロードや再起動のあともオンのままです。オフのあいだは、計測によるアプリの負担はほとんどありません。

### プロファイルを記録する

遅い操作がどこで時間を使っているかを知るには、それを記録します。

1. インスペクター（**i**）を開いて **Performance** タブに切り替え、デバイスを選んで **Record** を押します。
2. アプリで遅い操作をします。タップ、スクロール、画面を開くなど。
3. **Stop** を押します。

ターミナルで **t** を押すと、すべてのデバイスで同時に記録が始まり、もう一度 **t** を押すと止まります。各デバイスのプロファイルは `asuka-profile-<デバイス>-<時刻>.json` として現在のディレクトリに保存され、ターミナルには概要が表示されます。フラッシュの数、いちばん遅かったもの、ドロップしたフレーム、時間を多く使った関数です。

**Sample the app's functions** がオン（既定）のときは、アプリがどの関数で時間を使ったかもプロファイルに入ります。Asuka は実行中のコードを 1 秒に 1000 回のぞきます。Web ではこの項目はなく、プロファイルにはフラッシュとフレームが入ります。

### プロファイルを読む

Performance タブには記録が表示されます。

- **タイムライン**：フラッシュはフェーズごとに色分けされた棒で表され、その下にディスプレイがドロップしたフレームが赤で、さらにその下にあなたの関数の実行の様子が、呼び出し元を上、呼び出された関数を下にして並びます。スクロールで拡大縮小、ドラッグで移動、ダブルクリックで全体表示、ポインターを合わせると詳細が出て、フラッシュや関数をクリックするとその数値が表示されます。
- **Top functions**：関数ごとの自身の時間（その関数そのものの時間で、呼び出した先は含まない）と合計の時間（呼び出した先も含む）を、遅い順にファイルと行番号つきで並べます。括弧つきの名前はあなたのコードの外で使われた時間です。`(layout)`、`(props batch)`、`(frames batch)` はそれぞれのフェーズでのプラットフォームの処理、`(runtime)` はあなたの関数のあいだで Asuka 自身が行った処理です。
- **Flame graph**：呼び出しを木として表し、それぞれの幅がその時間に対応します。クリックするとその部分を拡大します。
- **Slowest flushes**：フラッシュを時間の長い順に、フェーズごとの時間と仕事量つきで並べます。クリックするとタイムライン上の位置に移動します。

まず見るところ：1 フレームより長くかかるフラッシュはフレームをドロップさせます。**app** フェーズが長ければ、コストはあなたのコードにあり、Top functions がどの関数かを教えてくれます（変更のたびに長いリストを並べ替える `let`、文字列を組み立てるループなど）。**layout** が長く measures が多いなら、大きなツリーがレイアウトし直されています。長い `Column` の代わりに `List` を使えば、画面に見えている行だけがレイアウトされます。**props** や **frames** が長く ops が多いなら、画面の多くの部分が一度に変わっています。

**Export trace** はプロファイルを [Perfetto](https://ui.perfetto.dev)（または `chrome://tracing`）で開けるファイルとして保存します。ファイルをドラッグすると、同じトラックとそれぞれのフラッシュの数値を見られます。**Export for speedscope** は [speedscope](https://www.speedscope.app) 用に保存し、そのフレームグラフ、Left Heavy ビュー、Sandwich ビューであなたの関数を調べられます。**t** で保存したファイルも Perfetto で開けます。

プロファイルは開発ビルドのものです。あなたのコードは `asuka dev` の開発用アプリの中で動くので、事前にコンパイルされるリリースビルドより遅くなります。読むべきなのは比率、つまりどのフェーズか、どの関数かです。

## エラーとそのコード

すべてのエラーと警告にはコードがあります。コードは、報告しているルールの名前です。ターミナルには、コードと一緒に、ヘルプ（あれば）とコードのページが表示されます。

```
app.asuka:14:9: error[write-in-binding]: can't assign to count here
  = help: what the UI follows is computed, not changed; change state in a handler (on press { … }), a fn, a task or an effect
  = see https://asuka.egoist.dev/docs/errors/write-in-binding
```

`asuka explain write-in-binding` を実行すると、そのページがターミナルに、あなたの言語（`LANG`）で、インストールしたバージョンのものが表示されます。ルールがある理由、破ったときの直し方、ルールを破るプログラムと破らないプログラムです。すべてのコードは[エラーコード](errors/README.md)にあります。

`asuka check --json` と `asuka test --json` は、代わりに 1 行に 1 つの JSON オブジェクトを書き出します。ツールやコーディングエージェント向けで、`code`、`severity`、`file`、`range`（行と列は 1 から）、`message`、`help`、`url` を持ち、一部のプラットフォームだけのものには `platforms` も付きます。エディターにもコードが表示され、そのページにリンクされます。

`asuka dev`、`asuka run`、`asuka test` で動かしているあいだは、コアも状態の中で見つけた問題をコード付きで報告します。互いを起こし続けるエフェクト（`effect-loop`。エフェクトの行と、最後に書き込んだ状態も示します）、使ってもいない別の load を待った load（`load-waterfall`）、`loading` を読むものがないまま前の答えを 2 秒表示している load（`long-hold`）、1,000 を超えるバインディングを 2 回実行させた書き込み（`wide-fanout`）、同じ更新の中でバインディングをもう一度実行させたエフェクトの書き込み（`effect-in-effect-pass`）です。コードの場所ごとに 1 回だけ、開発用アプリのログと一緒に表示されます。リリースビルドではこれらを検査しませんが、クラッシュレポートにはパニックのコードが記録されます。

## エディター

`asuka lsp` は Asuka の言語サーバーです。`.asuka` ファイルに対して、入力中の診断、補完、`///` のドキュメントを表示するホバー、定義へのジャンプ、参照の検索、名前の変更、フォーマット（`asuka fmt` と同じもの）、シンボル、シグネチャヘルプ、セマンティックハイライトを提供します。保存していない変更も含めて、編集中のパッケージと、それをインポートするパッケージをチェックします。

VS Code 用の拡張機能は `editors/vscode` にあります。この言語のハイライトを加え、`asuka lsp` を実行し（`PATH` にある `asuka`、または `asuka.server.path` で指定したもの）、プレビューを表示し、`asuka dev` が動かすアプリをデバッグします（[デバッガー](#デバッガー)を参照）。

```sh
cd editors/vscode
npm install
npx @vscode/vsce package
code --install-extension asuka-0.1.0.vsix
```

Zed 用の拡張機能は `editors/zed` にあります。Asuka の tree-sitter 文法（`editors/tree-sitter-asuka`）によるハイライト、アウトライン、括弧の対応、インデント、テキストオブジェクトに加え、`test`、`bench`、`app` ごとの実行ボタンを備え、`asuka lsp` を実行します。使うのは `PATH` にある `asuka`、または Zed の設定の `lsp.asuka.binary.path` で指定したものです。どちらもなければ、Asuka の最新リリースの CLI をダウンロードします。インストールは、コマンドパレットの **zed: install dev extension** で `editors/zed` ディレクトリーを選びます。Zed は Rust でビルドするので、[rustup](https://rustup.rs) で Rust を入れておいてください。

```json
{
  "lsp": {
    "asuka": {
      "binary": { "path": "/path/to/asuka", "arguments": ["lsp", "--verbose"] }
    }
  }
}
```

言語サーバーは、各 `preview` ブロックの上に **▶ Preview** を表示します。これはコードレンズで、VS Code やコードレンズを表示できるエディターに出ます。クリックすると、そのファイルのアプリを実行している `asuka dev` が、デバイスにそのプレビューを表示します（[プレビュー](#プレビュー)）。エディターはアプリのディレクトリから `asuka dev` を見つけ、動いていなければそこで `asuka dev` を起動するよう案内します。VS Code では、コマンド **Asuka: Show the App** でアプリに戻れます（**Asuka: Show Preview** はコードレンズが実行するコマンドで、カーソルのある位置のプレビューを表示します）。

LSP クライアントを備えたエディターなら、どれでも使えます。`asuka lsp` を実行すると、標準入出力で LSP 3.17 を話し、`.asuka` ファイルを扱い、`asuka.toml` のあるディレクトリーをルートにします。Neovim と Helix の設定は `editors/vscode` の README にあり、それらのハイライトには tree-sitter 文法 `editors/tree-sitter-asuka` を使えます。

## スナップショットとスクリプト

デスクトップのアプリは、いくつかの環境変数を受け付けます。これらを使うと、アプリに特定の状態を表示させてキャプチャーできるので、変更を目で確かめたり、CI で確認したりするのに便利です。リリースビルドの実行ファイルか、`asuka dev`（自身の環境変数を開発用アプリに渡します）に付けて実行します。

```sh
ASUKA_SNAPSHOT=shot.png ./MyApp.app/Contents/MacOS/MyApp            # ウィンドウが表示されたら PNG に保存して終了
ASUKA_SNAPSHOT=shot.png ASUKA_DUMP=1 asuka dev                      # あわせてビューツリーを shot.png.txt に書き出す
ASUKA_SCRIPT="tap:Add;tap:Add" ASUKA_SNAPSHOT=shot.png asuka dev    # 先に操作を実行する
```

- `ASUKA_SNAPSHOT`：ウィンドウが表示されたら（スクリプトがあればその実行後に）、ウィンドウを PNG に書き出して終了します。`ASUKA_SNAPSHOT_STAY=1` を指定すると、終了せずにアプリを実行し続けます。macOS ではウィンドウサーバーが合成したウィンドウの画像（シートも含む）なので、マテリアルや Liquid Glass も画面どおりに写ります。ファイル名が `*.content.png` なら、タイトルバーを除いたコンテンツだけを書き出します。
- `ASUKA_DUMP`：その PNG の隣にビューツリーを書き出します。各ビューの種類、フレーム、表示内容が含まれます。
- `ASUKA_SCRIPT`：スナップショットの前に、`;` で区切った操作を順に実行します。使える操作は、`tap:<text>`（そのテキストを表示しているビュー。ボタンのタイトル、テキスト、タブ、サイドバーの行、セグメントなど）、`type:<text>`（フォーカスのある入力欄に入力）、`back`、`key:<shortcut>`（`ctrl+shift+k`）、`menu:<item>`（メニューバーの項目）、`escape`、`close`（使用中のウィンドウを閉じる）、`wait:<duration>`（`500ms`）、`waitfor:<file>`（そのファイルができるまで待つ。続けるタイミングをテストが知らせる）、`until:<text>`（ウィンドウにそのテキストが表示されるまで待つ。最長 1 分）、`snap:<file>` です。

## ビルドキャッシュ

ビルドでコンパイルしたものやダウンロードしたものは Asuka のキャッシュに保存され、このコンピューター上のすべてのアプリで共有されます。2 つ目のアプリをビルドするときや、少し変更してからビルドし直すときは、新しい部分だけがコンパイルされます。あるプラットフォーム向けの最初のビルドでは、そのプラットフォーム向けにビルド済みの Asuka のライブラリを、CLI のバージョンの GitHub リリースから一度だけダウンロードし、CLI に含まれるチェックサムと照合します（このコンピューター自身向けのものは、インストールスクリプトと `asuka upgrade` があらかじめダウンロードしておきます）。プロキシーの設定（`HTTPS_PROXY`、`NO_PROXY`）もそのまま使われます。ミラーを使うには、リリースの `asuka-prebuilt-*.tar.gz` ファイルの置き場所を `ASUKA_PREBUILT_URL` に指定します。URL を指定した場合、その中の `{version}` は CLI のバージョンに置き換えられます（`ASUKA_PREBUILT_TOKEN` を設定すると、bearer トークンとして送られます）。ネットワークにつながらないコンピューターでは、これらのファイルをコピーしたディレクトリを指定することもできます。Swift のライブラリは、ビルドに使われた Xcode か、それより新しい Xcode でのみ使われます。Xcode がそれより古い場合は、代わりにお使いのコンピューターで一度だけコンパイルされます。

- `asuka cache stats` は、キャッシュの場所とサイズ、ビルドが必要なものをキャッシュから見つけられた回数を表示します。
- `asuka cache clean` はキャッシュを空にします。次のビルドでは、すべてがコンパイルし直されます。
- キャッシュは 10 GB 以内に保たれ、最も長く使われていないものから削除されます。`ASUKA_CACHE_MAX` で別の上限を（`ASUKA_CACHE_MAX=20G`、`500M`、上限なしなら `0`）、`ASUKA_CACHE` で別の場所を指定できます。

## よくある問題

- **`cbuild: no C compiler`**：システムの C コンパイラー（Xcode のコマンドラインツール、`build-essential`、LLVM）をインストールするか、Zig をインストールして `ASUKA_CC=zig` を指定します。`building for the web needs Zig` と `cross-compiling for ... needs Zig` の場合は、[Zig](https://ziglang.org/download) をインストールしてください。Zig は Web 向けや、ほかのシステム向けにビルドします。
- **`no iOS simulator SDK (install Xcode)`**：Xcode をインストールして一度起動し、Xcode の設定の「Components」で iOS シミュレーターのランタイムを追加します。`no iPhone simulator; add one in Xcode` や `no simulator "..."` は、その名前のシミュレーターがないという意味です。シミュレーターの一覧は `xcrun simctl list devices` で確認できます。
- **iPhone の準備ができていない**：`... isn't paired with this Mac`（ケーブルで接続し、ロックを解除して「信頼」をタップ）、`... isn't reachable`（ケーブルで接続するか、Mac と同じ Wi-Fi でスリープを解除）、`... has Developer Mode off`（「設定」›「プライバシーとセキュリティ」›「デベロッパモード」）、`... is locked`（ロックを解除）。接続しているのに `no iPhone or iPad is connected` と表示される場合は、`xcrun devicectl list devices` に表示されるか確かめてください。
- **`Xcode couldn't make the development profiles`**：チームの Apple ID で Xcode にサインインするか（Xcode ›「設定」›「アカウント」）、App Store Connect API キーを設定してください。ほかのチームが持っている bundle ID なら、`asuka.toml` で別の `id` にする必要があります。`the keychain has Apple Development certificates of N teams` の場合は、`--team` でチームを選んでください。
- **`the player hasn't connected yet`**：iPhone をケーブルでつないでロックを解除するか、Mac と同じネットワークにつなぎ、ローカルネットワークへのアクセスを許可し、Mac のファイアウォールで `asuka` が接続を受け付けられるようにしてください（「システム設定」›「ネットワーク」›「ファイアウォール」）。
- **`no Android SDK: install Android Studio or set ANDROID_HOME`**：Asuka は `ANDROID_HOME`、`ANDROID_SDK_ROOT` の順に探し、次に Mac なら `~/Library/Android/sdk`、Windows なら `%LOCALAPPDATA%\Android\Sdk`、Linux なら `~/Android/Sdk` を探します。
- **`no Android NDK`**：Android Studio の SDK Manager（SDK Tools、NDK）から NDK をインストールします。Asuka は、このコンピューター向けのビルドがあるもののうち最新のものを使います（Windows の PC では、Arm でも `windows-x86_64`）。
- **`no Android device or emulator`**：Android Studio の Device Manager で AVD を作るか、実機を接続します。Asuka が起動したエミュレーターについては、起動が完了するまで最大 4 分待ちます（`the emulator didn't boot`）。
- **Java**：Gradle にはバージョン 17〜24 の JDK が必要です。`JAVA_HOME` がその範囲ならそれが使われ、そうでなければ Android Studio に同梱の JDK が使われます。Android Studio はインストーラーか JetBrains Toolbox が置いた場所から探します（Windows では Program Files か `%LOCALAPPDATA%\Programs`）。それもなければ、インストール済みの JDK のうち範囲内で最も新しいものが使われます。どれもないときはビルドがそう伝えるので、`JAVA_HOME` をその範囲の JDK に設定してください。
- **Android の初回ビルドが遅い**：初回だけ、Gradle が自分自身と Android のライブラリをダウンロードするためです。
- **実機にリリースビルドが入っている**：`asuka build` でインストールしたアプリ（署名鍵が異なります）は、開発用アプリをインストールするために、データごとアンインストールされます。
- **`asuka dev --platform windows runs the app on this computer`**：`asuka dev` で Windows のアプリを実行できるのは、Windows 上だけです。ほかのシステムでは `asuka build --platform windows` でビルドし、できたフォルダーを PC にコピーしてください。
- **Linux での `... isn't installed`**：アプリには GTK 4.14 以降と libadwaita 1.5 以降が必要です。また、パッケージによっては独自のライブラリが必要です。`WebView` には WebKitGTK 6.0、動画とオーディオには GStreamer、セキュアストレージには libsecret が必要です。足りないライブラリはエラーメッセージに示されるので、ディストリビューションのパッケージマネージャーでインストールしてください。
- **Linux のアプリが開かない**：アプリにはディスプレイが必要です。SSH 経由や CI では Xvfb（`xvfb-run -a`）の下で実行し、D-Bus を使う機能のためにセッションバス（`dbus-run-session`）も用意してください。
- **最初からやり直す**：Asuka のビルド、キャッシュ、アプリの開発用データは、Asuka のキャッシュディレクトリにあります。場所は Mac では `~/Library/Caches/asuka`、Linux では `~/.cache/asuka`、Windows では `%LocalAppData%\asuka` です。`asuka cache clean` でこのディレクトリを空にすると、データのない状態から、すべてをビルドし直せます。

## asuka.toml

`asuka dev` と `asuka build` は、同じ `asuka.toml` を読み込みます。キーについては [asuka.toml のリファレンス](asuka-toml.md)を、リリースに向けてそれらがどう組み合わさるかについては[配布](shipping.md#asukatoml)を参照してください。
