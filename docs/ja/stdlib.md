# 標準ライブラリとプラットフォーム SDK

Asuka には 2 種類のパッケージが付属しています。どちらも `asuka` CLI に含まれているので、`asuka add` は要りません。インポートすればそのまま使えます。

- **標準ライブラリ**（`std/...`）：言語そのもののライブラリです（JSON、時刻、URL、正規表現、ファイル、HTTP、SQLite、store、Markdown、グラフなど）。どのプラットフォームでも同じように動きます。
- **プラットフォーム SDK**（`platform/...`）：デバイス（カメラ、位置情報、Bluetooth、センサー）、OS のサービス（通知、共有シート、Dock とトレイ、キーチェーン）、ストア（購入、Apple Pay、レビュー）をラップするパッケージです。

```asuka
import std/http
import std/store

state units = store.read("units", "metric")
```

以前のバージョンの `asuka/...` というパスをインポートすると、そのパッケージの今の名前が表示されます（`asuka/camera is platform/camera now`）。

標準ライブラリのほとんどのパッケージはプラットフォームのコードを必要としません。Asuka で書かれていて、Asuka で書けない部分はランタイム自身の C が担うので、どこでも同じように動きます（`std/json`、`std/math`、`std/embed` はコンパイラーの一部です）。それ以外のパッケージ（とプラットフォーム SDK のほとんど）は、ほかの[ネイティブパッケージ](native.md)と同じで、各プラットフォームがそれぞれの API で動かします（iOS と macOS では URLSession、Android では Android 自身のクラス、Web ではブラウザーの API、Windows と Linux では C）。そのため、そのプラットフォームのアプリと同じように振る舞います。

ネイティブパッケージのコードがないプラットフォーム（`asuka test` で動かすアプリにはまったくありません）では、それを必要とする処理は `unsupported` エラーを投げます。そのとき `std/store` は何も保存せず、読み込むとデフォルト値が返ります。

`asuka test` では実行のたびに同じ結果になります。`time.now()` は 2026-01-01T00:00:00Z から始まり、テストの時間（`sleep`）に合わせてだけ進みます。ローカルのタイムゾーンは UTC で、各テストには `fs.appDir()` として専用の空のディレクトリがあり、`configDir()`、`cacheDir()`、`logDir()` もその中にあります。Web ではアプリにまだディレクトリがないので、`std/fs` の呼び出しはエラーを投げます。

デバイスまわりのパッケージ（`location`、`sensors`、`purchase`、`pay`、`appleauth`、`nfc`、`bluetooth`）にはテスト用のフェイクがあります。`location.fake()` や `purchase.fake(products)` などは、プラットフォームの実装の代わりに、テストが操作する Asuka の実装（端末を動かす、購入を承認する、タグをかざす、ペリフェラルを加える）をパッケージに与えます。詳しくは[テスト](testing.md#プラットフォームのサービスとネイティブパッケージ)を参照してください。

## ここにないパッケージ

標準ライブラリにもプラットフォーム SDK にもないものは[パッケージ](packages.md)（`asuka add`）から入手します。何もラップしていないプラットフォームの API なら、自分でネイティブパッケージを作ります（[ネイティブコード](native.md)）。
