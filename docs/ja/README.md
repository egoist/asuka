# Asuka ドキュメント

<!-- repository-only:start -->
[English](../README.md) · [简体中文](../zh/README.md)
<!-- repository-only:end -->

Asuka を使うと、iOS、Android、macOS、Windows、Linux、Web 向けのアプリを、各プラットフォーム純正のウィジェットで作れます。アプリは、インターフェースのために作られた言語 **Asuka** で書きます。コンポーネントは何を表示するかを宣言し、状態は何が変わるかを表します。状態が変わると、それを読んでいるプロパティだけがプラットフォームのビューに送られます。ツリーの差分を取ることはありません。

```asuka
component Counter {
  state count = 0

  SafeArea {
    align: .center; justify: .center; gap: 16

    Text("Count: {count}") { font: .largeTitle }
    Button("Add") {
      variant: .filled
      on press { count += 1 }
    }
  }
}

app { Counter() }

test "counts taps" {
  let app = mount(Counter())
  app.tap("Add")
  app.expect("Count: 1")
}
```

## 仕組み

Asuka は、アプリのコンポーネントと状態、レイアウト（CSS の仕様どおりの flexbox と grid）、そして待ちを伴う処理（非同期関数、タスク、タイマー）を受け持ち、プラットフォーム純正のビューを作成・更新します。更新するのは、フレームごとに変わった部分だけです。

| プラットフォーム | 使うビュー |
| --- | --- |
| iOS | UIKit |
| Android | Android Views と Material 3 |
| macOS | AppKit |
| Windows | Win32 とコモンコントロール（Windows 11 の見た目で描画） |
| Linux | GTK 4 と libadwaita |
| Web | ページの DOM とブラウザー標準のコントロール |

たとえばテキストフィールドは、プラットフォームに応じて `UITextField`、`EditText`、`NSTextField`、`EDIT` コントロール、`GtkEntry`、`<input>` のいずれかになります。画面のスタックなら、`UINavigationController`、戻るジェスチャーに対応した Material のアプリバー、戻るボタンの付いた Mac のウィンドウのツールバー、libadwaita のナビゲーションビューのいずれかです。そのため、スタイルを何も指定しないアプリは、そのプラットフォームのほかのアプリと同じ見た目になり、アクセシビリティやテキスト入力、スクロールもほかのアプリと同じように振る舞います。

開発中は、`asuka dev` がアプリを動かします。実行先は、シミュレーター、エミュレーター、実機、手元のコンピューター、ブラウザーから選べます。保存した変更は数ミリ秒でアプリに届き、アプリの状態も画面もそのまま残ります。リリースビルドでは、プラットフォーム自身のコンパイラーでアプリを事前にコンパイルします。インタープリターもガベージコレクターもないので、処理が止まることもありません。

一つのアプリが、どのプラットフォームでもそのまま動きます。スマートフォンでは画面全体に表示され、デスクトップではユーザーがサイズを変えられるウィンドウになります。デスクトップでは、ウィンドウを追加で開いたり、キーボードショートカット付きのメニューバーを持たせたり（スマートフォンでは無視されます）もできます。あるプラットフォームにない機能を扱うパッケージ（たとえば Mac でのセンサーやホーム画面ウィジェット）は、そのプラットフォームでは「利用できない」と答えます。そのためアプリは、使えるかどうかを確かめたうえで、その機能なしで動作できます。

アプリが動作するのは、iOS 16、Android 7 (API 24)、macOS 11、Windows 10 以降と、GTK 4.14 以降および libadwaita 1.5 以降を備えた Linux、そして最新のブラウザーです。`asuka` CLI は単体のプログラムで、コマンド一つでインストールできます（[はじめに](getting-started.md#cli-のインストール)）。あるプラットフォーム向けにビルドするには、そのプラットフォームのツール（Xcode、Android SDK と NDK）と C コンパイラー（システムのもの、または Zig）が必要です。
