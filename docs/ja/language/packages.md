# ファイル、パッケージ、インポート

ソースファイルの拡張子は `.asuka` です。ソースファイルを入れたディレクトリが一つの**パッケージ**になります。同じパッケージのファイルどうしは、何もインポートしなくても互いの宣言が見えます。ほかのパッケージから見えるのは、`pub` を付けた宣言だけです。

```asuka
import std/http                 // 標準ライブラリ
import platform/camera          // プラットフォーム SDK
import @acme/charts               // 依存パッケージ（asuka add @acme/charts）
import ./components               // このパッケージと同じ階層にあるパッケージ
import ./model.{Message, Folder}  // パッケージ名を付けずに使う名前
import ./theme as t               // 短い別名
import ../model                   // 1 つ上のディレクトリにあるパッケージ
```

パッケージの名前は、パッケージ名を通して使います（`http.get(url)`、`components.Card("Hi")`）。パッケージ名はパスの最後の部分です。最後の部分が名前として使えないパッケージ（`@acme/line-charts`）は、`as` で名前を付けてインポートします。プレリュード（組み込みの型、要素、関数）はインポートする必要がありません。`std/...` と `platform/...` のパッケージは CLI に付属していて、一覧は[標準ライブラリとプラットフォーム SDK](../stdlib.md)にあります。ほかのパッケージには `std/` や `platform/` で始まる名前を付けられません。

文と宣言は行末で終わります。一行に複数書くときは `;` で区切ります。演算子、カンマ、開き括弧で終わる行は、次の行に続きます。

コメントは `// …` と `/* … */` です。`///` のコメントはその下にある宣言のドキュメントになり、エディターに表示されます。

## 特定のプラットフォーム向けのファイル

ファイル名がプラットフォームのサフィックスで終わるファイルは、そのプラットフォーム向けにアプリをビルドするときだけパッケージに含まれます。サフィックスは `_ios`、`_android`、`_macos`、`_windows`、`_linux`、`_web` のほか、複数のプラットフォームをまとめた `_desktop`（macOS、Windows、Linux）と `_mobile`（iOS、Android）があります。プラットフォームごとのファイルはそれぞれ同じ名前を宣言でき、パッケージのほかのファイルはそれをふつうの宣言と同じように使います。

```asuka
// feedback_mobile.asuka：iOS と Android
pub fn confirm() { haptic(.success) }

// feedback_desktop.asuka：macOS、Windows、Linux
pub fn confirm() { announce("Done") }

// feedback_web.asuka
pub fn confirm() {}
```

1 つの名前は、どのプラットフォームでも 1 回だけ宣言します。すべてのプラットフォームに含まれるファイルで宣言するか、その名前を持つプラットフォームごとのファイルでそれぞれ宣言するかのどちらかです。すべてのプラットフォームに含まれるファイルとあるプラットフォームのファイルの両方で宣言した名前や、あるプラットフォームで同時に含まれる 2 つのファイル（`feedback_desktop.asuka` と `feedback_linux.asuka`）の両方で宣言した名前は、どのプラットフォーム向けにビルドしてもエラーになります。サフィックスだけの名前のファイル（`linux.asuka`）は、ふつうのファイルです。

どのパッケージもファイル名で同じように扱われます。アプリのパッケージも、依存パッケージも、標準ライブラリも同じです。ビルドされるのは常にどれか 1 つのプラットフォーム向けです。`asuka dev` と `asuka build` はアプリを動かすプラットフォーム向けに、`asuka test` は `--platform` でほかを指定しない限り iOS 向けに、プログラムは実行するコンピューター向け（または `--target` の指定先向け）にビルドします。`asuka check` はプラットフォームごとにファイルをチェックし、エラーがすべてのプラットフォームのものでないときは、どのプラットフォームのエラーかを示します。たとえば一部のプラットフォームのファイルでしか宣言していない名前は、ほかのプラットフォームで使っている箇所がエラーになります。エディターは、あるプラットフォームのファイルをそのプラットフォームのファイルと合わせて読み、それ以外のファイルは iOS のファイルと合わせて読みます。エラーはすべてのプラットフォームのものを表示します。1 つのファイルの中でプラットフォームごとにコードを分けるには、[`@platform`](control-flow.md#特定のプラットフォーム向けのコード) を使います。

## アプリ、プログラム、ライブラリ

パッケージはエントリーポイントになるか、ライブラリになるかのどちらかです。`app { }` ブロックを持つパッケージはアプリで、このブロックが表示する内容になります（[ナビゲーション](navigation.md#ナビゲーション)を参照）。ファイルで `fn main()` を宣言しているパッケージは**プログラム**、つまりコマンドラインツールです。`main` は引数を受け取らず（引数は `os.args()` で読みます）、値も返さず（`os.exit(code)` で終了コードを指定して終了します）、`async` にすることもエラーを投げることもできます。`main` が終わるとプログラムも終わります。どちらも持たないパッケージはライブラリで、ほかのパッケージからインポートされます。1 つのパッケージがアプリとプログラムの両方になることはできず、プログラムはコンポーネントを宣言できません。ビューを表示しないからです。エントリーポイントを持つのは、アプリやプログラムを構成するパッケージだけです。インポートしたパッケージにある `main` は、ほかの関数と変わりません。詳しくは[プログラム](../programs.md)を参照してください。

```asuka
import std/os

fn main() {
  print("Hello, {os.args().first() ?? "world"}!")
}
```
