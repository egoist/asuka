# 多言語対応

Asuka のアプリは、使う人の言語でメッセージを表示し、その言語の読む向きに合わせてレイアウトされます。メッセージはカタログに置きます。カタログは言語ごとの JSON ファイルで、コンパイラーがこれを読み込みます。メッセージは `tr.key(…)` で表示し、アプリのコンパイル時にチェックされます。

```json
{
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}"
}
```

```asuka
component Inbox {
  state count = 3

  Column {
    Text(tr.unread(count: count))   // "3 unread messages"; "3 ungelesene Nachrichten"
    Button(tr.markAllRead()) { on press { count = 0 } }
  }
}
```

表示される内容は `count` に従い、言語が切り替われば新しい言語にも従います。そのためのコードを書く必要はありません。

## はじめる

```sh
asuka i18n init          # locales/en.json
asuka i18n add de ar     # locales/de.json と ar.json（翻訳すべきメッセージ入り）
```

カタログを入れた `locales` ディレクトリがあるアプリなら、設定は要りません。カタログが別の場所にある場合や、アプリを英語以外の言語で書いている場合は、`asuka.toml` で指定します。

```toml
[i18n]
dir = "translations"
source = "ja"
```

`source`（デフォルトは `en`、カタログが一つしかなければその言語）は、アプリを書いている言語です。そのカタログにはすべてのメッセージがあり、ほかの言語のカタログはそれにフォールバックします。アプリが提供する言語は、このディレクトリにあるファイルで決まります。ファイル名は [BCP 47](https://www.rfc-editor.org/info/bcp47) のタグにします（`de.json`、`pt-BR.json`、`zh-Hans.json`）。

生成するものも、インポートするものもありません。`asuka dev` はコンパイルのたびにカタログを読み込むので、翻訳は保存するとすぐに反映されます。リリースビルドでは、カタログはアプリに組み込まれてコンパイルされます。

## カタログ

カタログは、メッセージを集めた [ARB](https://github.com/google/app-resource-bundle) 形式のオブジェクトで、キーがメッセージの名前になります。ソースの言語のカタログでは、`@` を付けたキーの下にメッセージの説明も書きます。これは翻訳者のためのもので、エディターのホバー表示にも使われます。

```json
{
  "@@locale": "en",
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}",
  "@unread": {
    "description": "Above the list of messages.",
    "placeholders": { "count": { "type": "int", "example": "3" } }
  },
  "markAllRead": "Mark all as read",
  "greeting": "Hello, {name}!",
  "lastSeen": "Last seen {when, date, medium} at {when, time, short}",
  "storage": "{used, number, percent} of your storage is used",
  "@storage": { "placeholders": { "used": { "type": "double" } } }
}
```

キーは英字で始まり、そのあとに英字、数字、`_` が続きます。`tr.` のあとにはキーをそのまま書きます（`tr.markAllRead()`）。キーに階層はありません。関連するメッセージには `inboxTitle` と `inboxEmpty` のように共通の接頭辞を付けてください。エディターの補完でまとめて並びます。

メッセージのプレースホルダーが、呼び出しの名前付き引数になります（`tr.greeting(name: "Ada")`）。引数が一つだけのメッセージなら、名前を省いて `tr.greeting("Ada")` とも書けます。引数の型はプレースホルダーの型で決まります。

| プレースホルダー | 受け取る値 |
|---|---|
| `String`、`Object` | `string` |
| `int` | `int` |
| `double`、`num` | 数値：`int` または `float` |
| `DateTime` | 時刻：`Time`（std/time のもの。`time.now()` が返す値）、または 1970 年からのナノ秒 |

型を指定しない場合、`plural`、`selectordinal`、`number` で数える引数は `int`、`date` や `time` の引数は `DateTime`、それ以外は `String` になります。

ソースのカタログにないキーを使ったり、メッセージが受け取らない引数を渡したり、必要な引数を省いたり、型の違う引数を渡したりすると、呼び出した箇所でエラーになります。

```
app.asuka:8:13: locales/en.json has no message unred (did you mean tr.unread?)
app.asuka:9:10: tr.greeting needs its argument name (a string): its message is "Hello, {name}!"
```

## メッセージ

メッセージは ICU MessageFormat で書きます。ARB ファイル、Android、Format.JS で使われている形式です。

| メッセージ | 表示される内容 |
|---|---|
| `Hello, {name}!` | その位置に `name` の値 |
| `{count, plural, one {# file} other {# files}}` | メッセージの言語における `count` の複数形カテゴリーに対応するケース。`#` は数値 |
| `{count, plural, =0 {No files} one {# file} other {# files}}` | `=0` はちょうど 0 のときのケースで、カテゴリーより先に判定される |
| `{n, plural, offset:1 =0 {Nobody} =1 {{host}} one {{host} and # other} other {{host} and # others}}` | `offset:1` を付けると、カテゴリーと `#` は `n - 1` で数える |
| `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` | 序数のカテゴリー：1st、22nd、103rd、11th |
| `{gender, select, female {She} male {He} other {They}} replied.` | 値と同じ名前のケース。なければ `other` |
| `{price, number}`、`{ratio, number, percent}`、`{n, number, integer}` | その言語の書き方の数値（1,234.5、1.234,5、12,34,567） |
| `{price, number, ::.00}`、`{n, number, ::group-off}` | 小数部をちょうど 2 桁にする、または桁区切りを付けない |
| `{price, number, ::currency/EUR}` | 通貨（ISO 4217 のコード）の金額。通貨記号はその言語の位置に、小数部はその通貨の桁数で（€1,234.50、1.234,50 €、¥1,235） |
| `{day, date, short}`、`{day, time, short}` | スタイル（`short`、`medium`、`long`、`full`）を指定した日付または時刻 |
| `{day, date, ::yMMMd}` | CLDR のスケルトンが指定するフィールドを、その言語の順序で並べた日付（Jan 5, 2026、5. Jan. 2026） |
| `{day}`（`DateTime` の引数） | 短い形式の日付と時刻 |

ケースは入れ子にできます。`plural`、`selectordinal`、`select` には必ず `other` のケースを書きます。複数形のカテゴリーは、メッセージの言語に対する [Unicode CLDR](https://cldr.unicode.org) のものです。英語は `one` と `other`、中国語と日本語は `other` だけ、ロシア語は `one`、`few`、`many`、`other`、アラビア語は六つあります。

アポストロフィーは、直後の波括弧か、plural のケースの中の `#` をエスケープします。`'{'` は `{` になり、アポストロフィーを二つ重ねると一つになります。それ以外のアポストロフィーはそのまま一つのアポストロフィーなので、`don't` はエスケープ不要です。

## コンポーネントの中で

メッセージは文字列で、アプリが表示している言語で返されます。バインディング（プロパティの値、`if` の条件、`let`）の中で使ったメッセージは、引数に従うのと同じように言語にも従います。言語が変わると、メッセージを使っているバインディングがそれぞれメッセージを取得し直し、ほかには何も実行されません。そのため、アプリが表示するテキストはすべて言語に従います。ボタンのタイトル、タブや画面のタイトル、フィールドのプレースホルダー、ビューのラベルも同じです。

```asuka
import std/time

component Mailbox {
  state count = 3

  Column {
    Text(tr.inboxTitle()) { font: .largeTitle }
    Text(tr.greeting(name: "Ada"))
    Text(tr.unread(count: count))
    Text(tr.storage(used: 0.42))
    Text(tr.lastSeen(when: time.now()))
    Button(tr.markAllRead()) { on press { count = 0 } }
    TextField { placeholder: tr.greeting(name: "…") }
  }
}
```

メッセージを返す関数も、バインディングの中から呼べば同じように言語に従います。

```asuka
fn summary(count: int) -> string = if count > 0 { tr.unread(count: count) } else { tr.allRead() }

component Summary(count: int) {
  Text(summary(count))
}
```

ハンドラーの中で使ったメッセージは、その時点の言語の文字列になります。アラートや通知のように、一度表示したら消えるものにはこれが適しています。言語はメインスレッドのものなので、`spawn` の中ではメッセージを取得できません。先に取得して、文字列として渡してください。

## アプリが表示する言語

アプリが表示する言語は一つで、std/i18n の `i18n.locale()` がそれを返します。アプリが対応している言語のうち、ユーザーがいちばんよく読める言語が選ばれます。判断には、ユーザーが優先する言語を、システムに並んでいる順に使います。たとえば `zh-TW` を読むユーザーには `zh-Hant` を選びます。該当するものがなければ、アプリのソースの言語になります。英語だけで書かれたアプリは、UIKit と同じく、中国語を読むユーザーにも英語で表示されます。

ユーザーが優先する言語は、システムの設定から取得します。

- **iOS と macOS**：「設定」の「言語と地域」にある優先する言語。
- **Android**：システムの言語。
- **Windows**：ユーザーの表示言語（「設定」の「時刻と言語」）。
- **Linux**：セッションの `LANGUAGE`。なければ `LC_ALL`、`LC_MESSAGES`、`LANG`。
- **Web**：ブラウザーの言語（`navigator.languages`）。

`i18n.setLocale("de")` を呼ぶと、何も作り直さずに、すぐに別の言語で表示されます。メッセージを使っているバインディングがそれぞれメッセージを取得し直し、アプリはレイアウトし直し、画面に出ているものの状態はそのまま保たれます。`i18n.setLocale("")` を呼ぶと、再びユーザーの言語に従います。アプリの言語を、それぞれその言語自身の名前で並べたメニューは次のようになります。

```asuka
import std/i18n

component LanguageMenu {
  let choices = [""] + i18n.languages()

  List {
    for tag in choices key tag {
      Row {
        justify: .spaceBetween
        on press { i18n.setLocale(tag) }
        Text(if tag.isEmpty() { tr.systemLanguage() } else { i18n.autonym(tag) })
        if tag == i18n.locale() {
          Symbol("checkmark") { color: .accent }
        }
      }
    }
  }
}
```

`i18n.autonym` は、言語のその言語自身での名前を返します（"Deutsch"、"简体中文"、"العربية"）。

選んだ言語は次回の起動以降も保持されます。システムがアプリの言語を保持している場所に保存されるので、システムの設定画面にもその言語が表示されます。

- **iOS と macOS**：アプリの `AppleLanguages`。「設定」でアプリごとの言語を選ぶと書き込まれるのもここです。UIKit と AppKit が表示する自分の文言（日付ピッカーの「キャンセル」、Mac の標準メニューなど）は、次回の起動からその言語になります。アプリ自身の文言はすぐに切り替わります。
- **Android**：Android 13 以降では `LocaleManager`。設定画面にも表示され、システムの文言もすぐに切り替わります。それより前のバージョンでは Asuka のプリファレンスに保存します。
- **Windows と Linux**：アプリごとの言語という仕組みがないため、アプリのデータディレクトリにあるファイルに保存します。
- **Web**：ページの `localStorage`。

ユーザーがシステムの設定で自分の言語やアプリの言語を変えると、アプリは実行中のままそれに従います（iOS ではシステムがアプリを再起動します）。

| std/i18n | |
|---|---|
| `locale()` | 表示している言語。アプリの言語のどれかのタグ |
| `setLocale(tag)` | `tag` の言語で表示し、その選択を保持する。`""` なら再びユーザーの言語に従う |
| `languages()` | アプリの言語。ソースの言語が先頭 |
| `preferredLanguages()` | ユーザーが読める言語。優先度の高い順 |
| `isRTL()` | アプリが右から左にレイアウトされているかどうか |
| `autonym(tag)` | 言語のその言語自身での名前 |
| `region()` | ユーザーの地域のフォーマット：`locale`、`firstWeekday`（1 が日曜日 …… 7 が土曜日）、`hourCycle`（12 または 24） |
| `formatLocale()` | 表示している言語にユーザーのフォーマットを組み合わせたもの：`en-GB-u-fw-mon-hc-h23` |
| `setLanguages(tags)` | カタログを使わず、テキストを自分で翻訳するアプリ向け：アプリが書かれている言語を、自分の言語を先頭にして伝える |

どれも、バインディングの中で読めば、読んだものの変化に追従します。

## メッセージの選ばれ方

メッセージは、カタログの言語のうち、求められた言語にいちばん合うものから選ばれます。`zh-TW` なら `zh-Hant`、`pt-AO` なら `pt-PT`、`en-AU` なら `en-GB` です。その言語にメッセージがなければ、CLDR の親ロケール（`en-AU`、`en-001`、`en`。`zh-Hant-HK`、`zh-Hant`）をたどってフォールバックし、最後はソースの言語になります。翻訳が欠けていても何も表示されないことはなく、ソースのメッセージが表示されます。その場合も、数値と日付は表示している言語の書き方になります。

## 数値と日付

メッセージは、数値と日付を表示している言語の書き方で書きます。自分で書くときは std/i18n を使います。

```asuka
import std/i18n
import std/time

component Stats(bytes: int, ratio: float) {
  Column {
    Text(i18n.formatNumber(1234567.891))              // 1,234,567.891; 1.234.567,891; 12,34,567.891
    Text(i18n.formatInt(bytes))                       // 1,234,567
    Text(i18n.formatPercent(ratio))                   // 25%; 25 %; ٢٥٪؜
    Text(i18n.formatCurrency("1234.5", "EUR"))         // €1,234.50; 1.234,50 €
    Text(i18n.formatDecimal("0.1234567890123"))        // 正確に：0.1234567890123
    Text(i18n.formatNumber(2.5, minFractionDigits: 2)) // 2.50
    Text(i18n.formatDate(time.now(), date: .full))     // Monday, January 5, 2026
    Text(i18n.formatDate(time.now(), date: .short, time: .short)) // 1/5/26, 1:07 PM
    Text(i18n.formatRelative(time.now().add(-3h)))   // 3 hours ago; vor 3 Stunden
  }
}
```

`formatCurrency` と `formatDecimal` は、書いたとおりの数値を受け取り、正確に書きます。[`std/decimal`](stdlib.md) の `Decimal` の `formatted(currency:)` は、そのテキストに対する `formatCurrency` です。金額の小数部はその通貨の桁数（ほとんどは 2 桁、円は 0 桁、クウェート・ディナールは 3 桁）で、通貨記号はその言語での書き方（`$`、`US$`、`CHF`）で、その言語が置く位置に付きます。

データは ICU やブラウザーの `Intl` と同じ CLDR のもので、アプリの言語の分だけが入ります。コンパイラーは、カタログの各言語の数字、区切り文字、通貨記号、パターン、月・曜日・午前午後などの名前をアプリに組み込み、アプリが提供しない言語のデータは何も入れません。カタログのないアプリは、英語の書き方で書きます。

`formatRelative(t)` は、時刻を今から見た言い方で書きます：「3 時間後」「2 日前」。その言語に決まった言い方があればそれを使います（「昨日」「先週」）。`numeric: true` なら常に数で書きます。`style:` は `.long`、`.short`（短縮形）、`.narrow`（最も短い形）のどれかです。Apple の `RelativeDateTimeFormatter` と同じように、デバイスのカレンダーで 0 でない最大の単位を選び、その言語の複数形で書きます。バインディングの中で読むと言語の変更には追従しますが、時間の経過には追従しません。時間が経ったら表示し直してください。

日付は、デバイスのタイムゾーンとグレゴリオ暦で書きます。UTC 以外のタイムゾーンは、ICU が名前で表すものでも、GMT からのオフセット（`GMT+8`）で書きます。時刻は、言語にかかわらず、ユーザーの地域のフォーマットにある 12 時間制か 24 時間制か（iOS では「設定」の「24時間表示」）に従います。テスト（`asuka test`）ではタイムゾーンが UTC になるので、どのコンピューターでも同じ日付になります。

## 右から左

右から左に書く言語では、コードを書かなくてもアプリが右から順にレイアウトされます。`Row` は右から並び、`justify` と `align` もそれに従い、テキストは右端から始まります。プラットフォームのビューも左右反転します（ナビゲーションバーとその戻るジェスチャー、タブバー、プッシュとポップ、スライダー、リストのスワイプアクション）。横方向の `Scroll` は右端から始まります。アプリの実行中にそうした言語へ、またはそうした言語から切り替えると、すぐにレイアウトし直されます。レイアウトは CSS の `direction` に従い、Chrome の結果と照らし合わせて検証しています。

位置を手で指定するときは次のようにします。

```asuka
component Card {
  View {
    padding: Edges(start: 16)       // テキストが始まる側に
    Text(tr.greeting(name: "Ada"))
    Symbol("chevron.forward") { absolute: true; end: 8 }   // テキストが終わる側から
  }
}
```

CSS と同じく、`left` と `right`（`Edges` のものも、`absolute` と一緒に使うものも）は文字どおりの位置から動きません。左右反転させたいもの、つまりほとんどすべてには `start` と `end` を使ってください。

`forward` や `backward` で向きを表す名前のシンボルは左右反転します（`chevron.forward`、`arrow.backward`）。`chevron.left` は反転しません。メディアプレイヤーの巻き戻しのように、どの言語でも左を向くもののためのシンボルです。

テキストの一行は、その文字自体の向きで読まれます。アラビア語のアプリの中にある英語の文は右側に置かれますが、ピリオドは文末に残ります。どちらの側に置くかはアプリの向きで決まり、文字の並びは Unicode の双方向アルゴリズムで決まります。右から左に書く言語のメッセージがラテン文字の名前や数字で始まる場合は、Asuka が先頭に右から左へのマーク（RLM）を付けるので、それでも右から読まれます。

電話番号、メディアプレイヤーのコントロール、コードエディターのように、どの言語でも同じ向きで読むものは、そう指定します。

```asuka
component Controls {
  Row {
    layoutDirection: .leftToRight
    Button(tr.previous()) { icon: "backward.fill" }
    Button(tr.play()) { icon: "play.fill" }
    Button(tr.next()) { icon: "forward.fill" }
  }
}
```

`i18n.isRTL()` はアプリの向きを返します。描画のように、自動では向きに従わないもののために使います。フレーム、`on layout`、`on scroll` は物理的な座標で、左端が基準です。

## 言語を試す

```sh
asuka dev --platform ios --lang de .       # この実行だけドイツ語で
asuka dev --platform ios --lang en-XA .    # [Šéļéçţ ƒîļéš one two]
asuka dev --platform ios --lang ar-XB .    # 各単語を右から左に、レイアウトも反転
asuka dev --platform ios --dir rtl .       # 翻訳なしで、どんなアプリも右から左に
```

`--lang` と `--dir` は、`asuka dev` が対応するすべてのプラットフォームで使えます。指定は開発用アプリが動かす内容に組み込まれるので、シミュレーター、実機、エミュレーター、デスクトップ、ブラウザーのどれでも、ユーザーの言語にかかわらず同じように表示されます。また、これらを指定している間は、`setLocale` は何も保存しません。

```sh
asuka dev --lang ar .                      # このコンピューターで：macOS、Windows、Linux
asuka dev --platform web --dir rtl .       # ブラウザーで
```

この二つの疑似ロケールを使うと、Android の疑似ロケールと同じように、翻訳がまだなくてもレイアウトをテストできます。`en-XA` は、ソースのメッセージの文字にアクセント記号を付け、長さを 3 分の 1 ほど伸ばし、角括弧で囲みます。プレーンなまま表示されるテキストはカタログに入っていません。切れてしまうテキストは、表示する場所が狭すぎます。いくつもの角括弧でできた文は断片の組み合わせなので、翻訳で語順を入れ替えられません。`ar-XB` では、左右反転しないものがわかります。疑似ロケールにカタログは要りません。手で起動した開発用アプリでは、`ASUKA_LOCALE=de` と `ASUKA_DIRECTION=rtl` で同じことができます。

## カタログのチェック

`asuka dev`、`asuka build`、`asuka i18n check` はカタログをチェックします。問題があれば、コンパイラーがカタログのファイル名と行番号を示して知らせます。次のものはエラーになり、処理が止まります。

- 正規のタグの名前が付いていないファイル、または `@@locale` がファイル名と異なるファイル
- パースできないメッセージ
- 翻訳にあってソースにないキー、または Asuka にメッセージがない `asuka.<key>` のキー
- 翻訳にあってソースのメッセージにない引数、または型に合わない使い方をしている引数（`plural` で数える `String` など）

次のものは警告で、処理は止まりません。翻訳に欠けているメッセージ（ソースの言語のメッセージが表示されます）、翻訳で省かれている引数、その言語にない複数形のケース（英語の `few`）や、その言語にあるのに欠けているケース（ロシア語の `few`。代わりに `other` が表示されます）、メッセージで使われていないプレースホルダーです。

## システムが表示するもの

`asuka build` は、カタログの言語を宣言します（iOS と macOS では `CFBundleLocalizations` と `.lproj`、Android では `locales_config`）。この宣言があるので、iOS と macOS は自分の文言をそれらの言語で表示し、「設定」にアプリの言語の選択肢が出ます。Windows と Linux には、アプリごとの言語という仕組みがありません。言語を宣言するのは Windows の MSIX だけで、Microsoft Store はそれをアプリの対応言語として表示します。Windows のインストーラーは、ユーザーの言語の `asuka.appName` でアプリを呼びます（[配布](shipping.md#windows)）。カタログの `asuka.<name>` のキーで、ビルドがそこに書き込む内容を翻訳できます。

```json
{
  "asuka.appName": "Notizen",
  "asuka.NSCameraUsageDescription": "Um Belege zu scannen.",
  "asuka.widget.steps.name": "Schritte",
  "asuka.widget.steps.description": "Deine Schritte heute.",
  "asuka.shortcut.newNote": "Neue Notiz"
}
```

## Asuka 自身の文言

プラットフォームが自分の文言を表示するので、Asuka 自身が表示する文言はわずかです。ボタンが一つだけのアラートのボタン、検索フィールドのプレースホルダー、デスクトップの「戻る」、Mac の「（アプリ名）について」「隠す」「終了」、ステッパーのラベルです。Asuka はこれらを、主要な言語に翻訳済みのものから、アプリが表示している言語で表示します。アプリのカタログにある `asuka.<key>` のキーはこれと照らし合わせてチェックされますが、アプリが独自に訳したものを Asuka が表示する仕組みはまだありません。
