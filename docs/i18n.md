# Languages

An Asuka app says its messages in the language of the people who use it, and is
laid out the way that language reads. Its messages live in catalogs, a JSON file
per language, which the compiler reads: `tr.key(…)` says one, checked as the app
compiles.

```json
{
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}"
}
```

```asuka
component Inbox {
  state count = 3

  Column {
    Text(tr.unread(count: count))   // "3 unread messages"; "3 ungelesene Nachrichten"
    Button(tr.markAllRead()) { on press { count = 0 } }
  }
}
```

What it says follows `count`, and follows the language when it changes, with no
code of yours.

## Starting

```sh
asuka i18n init          # locales/en.json
asuka i18n add de ar     # locales/de.json and ar.json, with the messages to translate
```

An app with a `locales` directory of catalogs needs no configuration. If they're
elsewhere, or the app is written in another language, say so in `asuka.toml`:

```toml
[i18n]
dir = "translations"
source = "ja"
```

`source` (default `en`, or the only catalog there is) is the language the app is
written in: its catalog has every message, and the others fall back to it. The
languages the app ships are the files of the directory, named after their
[BCP 47](https://www.rfc-editor.org/info/bcp47) tags: `de.json`, `pt-BR.json`,
`zh-Hans.json`.

There's nothing to generate and nothing to import: `asuka dev` reads the catalogs
as it compiles, so a translation shows on save, and a release build compiles them
into the app.

## Catalogs

A catalog is an object of messages, in the [ARB](https://github.com/google/app-resource-bundle)
format, whose keys name them. The source language's also describes them, under
the key with an `@`, for translators and for your editor's hover:

```json
{
  "@@locale": "en",
  "unread": "{count, plural, =0 {No unread messages} one {# unread message} other {# unread messages}}",
  "@unread": {
    "description": "Above the list of messages.",
    "placeholders": { "count": { "type": "int", "example": "3" } }
  },
  "markAllRead": "Mark all as read",
  "greeting": "Hello, {name}!",
  "lastSeen": "Last seen {when, date, medium} at {when, time, short}",
  "storage": "{used, number, percent} of your storage is used",
  "@storage": { "placeholders": { "used": { "type": "double" } } }
}
```

A key is a letter, then letters, digits and `_`, and `tr.` names it as it is:
`tr.markAllRead()`. Keys are flat: name related messages with a common start, as
`inboxTitle` and `inboxEmpty`, which sort together in your editor's completion.

A message's placeholders are its call's arguments, by name: `tr.greeting(name: "Ada")`. A
message of one argument may leave its name out, `tr.greeting("Ada")`. Their types
are the placeholders':

| Placeholder | Takes |
|---|---|
| `String`, `Object` | a `string` |
| `int` | an `int` |
| `double`, `num` | a number: an `int` or a `float` |
| `DateTime` | a time: a `Time` (std/time's, as `time.now()` gives), or nanoseconds since 1970 |

Without a type, an argument counted by `plural`, `selectordinal` or `number` is an
`int`, a `date` or `time` argument a `DateTime`, and any other a `String`.

A key the source's catalog doesn't have, an argument its message doesn't take, an
argument the call leaves out, or one of another type, is an error where you call it:

```
app.asuka:8:13: locales/en.json has no message unred (did you mean tr.unread?)
app.asuka:9:10: tr.greeting needs its argument name (a string): its message is "Hello, {name}!"
```

## Messages

Messages are ICU MessageFormat, the format of ARB files, of Android and of
Format.JS:

| Message | Says |
|---|---|
| `Hello, {name}!` | the value of `name` in its place |
| `{count, plural, one {# file} other {# files}}` | the case of `count`'s plural category in the message's language; `#` is the number |
| `{count, plural, =0 {No files} one {# file} other {# files}}` | `=0` is for exactly 0, before the categories |
| `{n, plural, offset:1 =0 {Nobody} =1 {{host}} one {{host} and # other} other {{host} and # others}}` | with `offset:1`, the categories and `#` count `n - 1` |
| `{place, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` | the ordinal category: 1st, 22nd, 103rd, 11th |
| `{gender, select, female {She} male {He} other {They}} replied.` | the case named after the value, else `other` |
| `{price, number}`, `{ratio, number, percent}`, `{n, number, integer}` | a number in the language's way (1,234.5; 1.234,5; 12,34,567) |
| `{price, number, ::.00}`, `{n, number, ::group-off}` | exactly two fraction digits, or no separators of thousands |
| `{price, number, ::currency/EUR}` | an amount of a currency, its ISO 4217 code: its symbol where the language puts it, its fraction digits (€1,234.50; 1.234,50 €; ¥1,235) |
| `{day, date, short}`, `{day, time, short}` | a date or a time in a style: `short`, `medium`, `long` or `full` |
| `{day, date, ::yMMMd}` | a date of a CLDR skeleton's fields, in the language's order (Jan 5, 2026; 5. Jan. 2026) |
| `{day}`, a `DateTime` | its short date and time |

Cases nest, and every `plural`, `selectordinal` and `select` has an `other` case.
The plural categories are those of the [Unicode CLDR](https://cldr.unicode.org)
for the message's language: `one` and `other` in English, only `other` in Chinese
and Japanese, `one`, `few`, `many` and `other` in Russian, six in Arabic.

An apostrophe quotes the next brace, or `#` in a plural case: `'{'` says `{`, and
two apostrophes say one. Any other apostrophe is just one, so `don't` needs no
quoting.

## In components

A message is a string, said in the language the app shows. Said in a binding (a
prop's value, an `if`'s condition, a `let`), it follows the language as it follows
its arguments: when the language changes, each binding that said a message says
it again, and nothing else runs. So every text the app shows follows, a button's
title, a tab's, a screen's, a field's placeholder and a view's label alike:

```asuka
import std/time

component Mailbox {
  state count = 3

  Column {
    Text(tr.inboxTitle()) { font: .largeTitle }
    Text(tr.greeting(name: "Ada"))
    Text(tr.unread(count: count))
    Text(tr.storage(used: 0.42))
    Text(tr.lastSeen(when: time.now()))
    Button(tr.markAllRead()) { on press { count = 0 } }
    TextField { placeholder: tr.greeting(name: "…") }
  }
}
```

A function that says a message is followed the same way where a binding calls
it:

```asuka
fn summary(count: int) -> string = if count > 0 { tr.unread(count: count) } else { tr.allRead() }

component Summary(count: int) {
  Text(summary(count))
}
```

Said in a handler, a message is what it says then: right for what's shown once
and gone, an alert or a notification. The language is the main thread's, so
`spawn` can't say one: say it first and pass the string.

## The language the app shows

The app shows one language, which `i18n.locale()` returns (std/i18n): of the
languages it's written in, the one the user reads best, by the languages they
prefer in the order the system lists them, as `zh-Hant` for a reader of `zh-TW`;
else the app's source language. An app written in English alone shows English to
a reader of Chinese, as UIKit does.

The languages the user prefers are the system's:

- **iOS and macOS**: the preferred languages of Settings' Language & Region.
- **Android**: the system's languages.
- **Windows**: the user's display languages (Settings' Time & language).
- **Linux**: the session's `LANGUAGE`, else `LC_ALL`, `LC_MESSAGES` or
  `LANG`.
- **The web**: the browser's (`navigator.languages`).

`i18n.setLocale("de")` shows another language at once, without rebuilding
anything: each binding that says a message says it again, the app lays out again,
and the state of what's on screen stays. `i18n.setLocale("")` follows the user's
languages again. A menu of the app's languages, each named in itself:

```asuka
import std/i18n

component LanguageMenu {
  let choices = [""] + i18n.languages()

  List {
    for tag in choices key tag {
      Row {
        justify: .spaceBetween
        on press { i18n.setLocale(tag) }
        Text(if tag.isEmpty() { tr.systemLanguage() } else { i18n.autonym(tag) })
        if tag == i18n.locale() {
          Symbol("checkmark") { color: .accent }
        }
      }
    }
  }
}
```

`i18n.autonym` names a language in itself ("Deutsch", "简体中文", "العربية").

The choice is kept across launches, where the system keeps an app's language so
that its Settings show it:

- **iOS and macOS**: the app's `AppleLanguages`, which is what Settings' language
  for the app writes. UIKit and AppKit say their own words (Cancel in a date
  picker, the Mac's standard menus) in it from the next launch; yours, at once.
- **Android**: `LocaleManager` on Android 13 and later, which its settings show, and
  the system's own words follow at once; Asuka's preferences before that.
- **Windows and Linux**, which have no language for an app: a file in the app's
  data directory.
- **The web**: the page's `localStorage`.

When the user changes their language or the app's in the system's settings, the app
follows as it runs (on iOS, the system relaunches it).

| std/i18n | |
|---|---|
| `locale()` | the language shown, a tag of the app's |
| `setLocale(tag)` | show `tag`'s language, kept; `""` the user's again |
| `languages()` | the app's languages, its source first |
| `preferredLanguages()` | the languages the user reads, most preferred first |
| `isRTL()` | whether the app is laid out right to left |
| `autonym(tag)` | a language's name in itself |
| `region()` | the user's regional formats: `locale`, `firstWeekday` (1 Sunday ... 7 Saturday), `hourCycle` (12 or 24) |
| `formatLocale()` | the language shown with the user's formats: `en-GB-u-fw-mon-hc-h23` |
| `setLanguages(tags)` | for an app without catalogs that translates its text itself: the languages it's written in, its own first |

Each of them read in a binding follows what it reads.

## Which message

A message is the one of the catalog's language that suits the language asked for
best: `zh-Hant` for `zh-TW`, `pt-PT` for `pt-AO`, `en-GB` for `en-AU`. When that
language lacks it, it falls back along CLDR's parent locales (`en-AU`, `en-001`,
`en`; `zh-Hant-HK`, `zh-Hant`), then to the source language: a missing translation
says the source's message rather than nothing, in the numbers and dates of the
language shown.

## Numbers and dates

Messages write their numbers and dates in the language shown's way, and std/i18n
writes yours:

```asuka
import std/i18n
import std/time

component Stats(bytes: int, ratio: float) {
  Column {
    Text(i18n.formatNumber(1234567.891))              // 1,234,567.891; 1.234.567,891; 12,34,567.891
    Text(i18n.formatInt(bytes))                       // 1,234,567
    Text(i18n.formatPercent(ratio))                   // 25%; 25 %; ٢٥٪؜
    Text(i18n.formatCurrency("1234.5", "EUR"))         // €1,234.50; 1.234,50 €
    Text(i18n.formatDecimal("0.1234567890123"))        // exact: 0.1234567890123
    Text(i18n.formatNumber(2.5, minFractionDigits: 2)) // 2.50
    Text(i18n.formatDate(time.now(), date: .full))     // Monday, January 5, 2026
    Text(i18n.formatDate(time.now(), date: .short, time: .short)) // 1/5/26, 1:07 PM
    Text(i18n.formatRelative(time.now().add(-3h)))   // 3 hours ago; vor 3 Stunden
  }
}
```

`formatCurrency` and `formatDecimal` take a number as it's written, exactly:
a [`std/decimal`](stdlib.md) `Decimal`'s `formatted(currency:)` is
`formatCurrency` of its text. An amount has its currency's fraction digits (two
for most, none for the yen, three for the Kuwaiti dinar) and the symbol the
language writes it with (`$`, `US$`, `CHF`), next to the number where the
language puts it.

Their data is CLDR's, as ICU and browsers' `Intl` have it, for the app's
languages: the compiler puts each catalog language's digits, separators,
currency symbols, patterns and names of months, weekdays and day periods into the app, and nothing
of the languages it doesn't ship. An app without catalogs writes English's.

`formatRelative(t)` says a time as it's seen from now: "in 3 hours", "2 days
ago", or a word the language has for it ("yesterday", "last week"), unless
`numeric: true`. `style:` is `.long`, `.short` ("3 hr. ago") or `.narrow`
("3h ago"). It picks the largest unit that isn't 0 on the device's calendar, as
Apple's `RelativeDateTimeFormatter` does, with the language's plural forms.
Read in a binding, it follows the language, not the clock: show it again as
time passes.

Dates are written in the device's time zone, in the Gregorian calendar; zones other
than UTC as offsets from GMT (`GMT+8`) where ICU names some. Times follow the user's
hour cycle, the 12 or 24 hours of their regional formats (Settings' 24-Hour Time
on iOS), whatever the language. In tests (`asuka test`) the zone is UTC, so a test
sees the same dates on every computer.

## Right to left

In a language written right to left, the app is laid out from the right, with no
code of yours: a `Row` runs from the right, `justify` and `align` follow it, text
starts on the right, and the platform's views mirror (the navigation bar and its
back gesture, the tab bar, push and pop, a slider, a list's swipe actions). A
horizontal `Scroll` starts at its right end. Switching to or from such a language
while the app runs lays it out again at once. Layout follows CSS's `direction`,
checked against Chrome's results.

What you place by hand:

```asuka
component Card {
  View {
    padding: Edges(start: 16)       // on the side text starts on
    Text(tr.greeting(name: "Ada"))
    Symbol("chevron.forward") { absolute: true; end: 8 }   // from the side text ends on
  }
}
```

`left` and `right` (of `Edges`, and with `absolute`) stay where they say, as in
CSS: use `start` and `end` for what should mirror, as nearly everything should.

Symbols named for a direction by `forward` or `backward` mirror: `chevron.forward`,
`arrow.backward`. `chevron.left` doesn't, for what's left in every language (a
media player's rewind, say).

A line of text reads as its own letters do: an English sentence in an Arabic app sits
on the right and keeps its full stop at its end. Its side comes from the app, its order
from the Unicode bidirectional algorithm. When a message of a right-to-left language
starts with a name or a number in Latin letters, Asuka starts it with a right-to-left
mark, so that it still reads from the right.

What reads the same way in every language, as a phone number, a media player's
controls or a code editor, says so:

```asuka
component Controls {
  Row {
    layoutDirection: .leftToRight
    Button(tr.previous()) { icon: "backward.fill" }
    Button(tr.play()) { icon: "play.fill" }
    Button(tr.next()) { icon: "forward.fill" }
  }
}
```

`i18n.isRTL()` says which way the app goes, for what doesn't follow by itself, as
a drawing. Frames, `on layout` and `on scroll` are physical, from the left.

## Trying a language

```sh
asuka dev --platform ios --lang de .       # the app in German, for this run
asuka dev --platform ios --lang en-XA .    # [Šéļéçţ ƒîļéš one two]
asuka dev --platform ios --lang ar-XB .    # each word right to left, and the layout
asuka dev --platform ios --dir rtl .       # any app right to left, untranslated
```

`--lang` and `--dir` work with every platform `asuka dev` runs: they're built
into what the player runs, so the simulator, a phone, the emulator, the
desktops and the browser show them alike, whatever the user reads, and
`setLocale` keeps nothing while they're given:

```sh
asuka dev --lang ar .                      # on this computer: macOS, Windows or Linux
asuka dev --platform web --dir rtl .       # in the browser
```

The two pseudo locales test layouts before any translation exists, as Android's do.
`en-XA` accents the letters of the source's messages, makes them a third longer and
brackets them: text that stays plain isn't in a catalog, cut text has too short a
space, and a sentence of several brackets is made of pieces a translation can't
reorder. `ar-XB` shows what doesn't mirror. They need no catalog. A player started
by hand reads `ASUKA_LOCALE=de` and `ASUKA_DIRECTION=rtl` the same way.

## Checking the catalogs

`asuka dev`, `asuka build` and `asuka i18n check` check them; the compiler says
what's wrong at the catalog's file and line. Errors stop them:

- a file not named after a canonical tag, or whose `@@locale` differs;
- a message that doesn't parse;
- a key a translation has and the source doesn't, or a key `asuka.<key>` Asuka has no
  message for;
- an argument a translation has and the source's message doesn't, or used in a way
  its type can't be (a `String` counted by `plural`).

Warnings don't: messages a translation lacks, which say the source language's;
arguments it leaves out; plural cases its language doesn't have (`few` in English) or
lacks (`few` in Russian, which says `other` in its place); placeholders a message
doesn't use.

## What the system shows

`asuka build` declares the catalogs' languages (`CFBundleLocalizations` and `.lproj`s on
iOS and macOS, a `locales_config` on Android): that's what makes iOS and macOS say their
own words in them and Settings offer the app's language. Windows and Linux have no
language for an app: only a Windows MSIX declares the languages, which the Microsoft
Store lists the app in, and the Windows installer calls the app by its `asuka.appName`
in the user's language ([Shipping](shipping.md#windows)). Keys `asuka.<name>` in the
catalogs translate what it writes there:

```json
{
  "asuka.appName": "Notizen",
  "asuka.NSCameraUsageDescription": "Um Belege zu scannen.",
  "asuka.widget.steps.name": "Schritte",
  "asuka.widget.steps.description": "Deine Schritte heute.",
  "asuka.shortcut.newNote": "Neue Notiz"
}
```

## Asuka's own words

Asuka says few words itself, since the platforms say theirs: an alert's only button, a
search field's placeholder, a desktop's Back, a Mac's About, Hide and Quit, and a
stepper's labels. Asuka says them in the language the app shows, translated into
the common languages. A key `asuka.<key>` of your catalogs is checked against
those; Asuka doesn't say an app's own version of them yet.
